# 빌드 캐시를 보존하면서 정리하기

ARM 빌드 화면의 **캐시 보존·정리 미리보기**에서 삭제 가능한 항목과 보존 이유를 먼저 확인합니다. 현재 사용 중인 이미지나 이력이 없는 기존 캐시를 삭제하지 않고, 추적한 오래된 캐시만 정리해 저장 공간을 줄입니다.

## 보존과 실행 조건

- Companion이 생성 사실과 성공 빌드 사용 시점을 기록한 의존성·런타임 이미지만 삭제 후보가 됩니다. 기존 미추적 이미지와 기존 Function 템플릿이 보고하지 않는 이미지는 유지합니다.
- 최근 성공한 잠금 파일 3종, 최근 30일 사용분, 생성 후 7일은 보존합니다. 현재 Function 이미지와 Function/Application 설정의 참조는 같은 잠금 파일의 캐시 쌍까지 보호합니다.
- 선택 리전의 모든 구획에서 Functions 참조를 조회하지 못하면 삭제하지 않습니다. 실행 중·미확인 빌드도 정리를 차단합니다. 다른 호스트·도구·리전에서 공유하는 저장소에서는 정리를 실행하지 않습니다.
- 미리보기 이후 사용 기록이나 참조가 달라지면 실행을 거부합니다. 삭제 직전 다시 조회하고 이미지 ID·etag를 고정합니다. 태그가 바뀌거나 여러 태그가 붙은 이미지도 보존합니다.
- 사용자가 해당 저장소의 자동 정리를 켜면 이후 성공 빌드 종료 시 같은 정책을 적용합니다. 자동 정리가 꺼진 저장소의 참조 전체를 매번 조사하지 않습니다. 시간 기반 데몬은 설치하지 않습니다.
- 결과 복구·포기는 캐시 사용 시점을 누락했을 수 있으므로 데이터 디렉터리 전체의 삭제를 30일 유예합니다. 빌드는 계속할 수 있습니다.

## 실제 정리 검증 · 2026-11-26

별도 `companion/verify-cache-retention` 저장소와 검증 Function을 사용했습니다. 기존 IAM·보안 규칙·Secret은 수정하지 않았습니다.

| 검증 | 결과 |
| --- | --- |
| 새 이미지 7개 | 현재 Function 1개, 설정 참조 1개, 최근 3종, 미추적 1개를 보존 |
| 오래된 비참조 캐시 | 1개만 자동 삭제, 남은 6개 실제 조회 확인 |
| 미리보기 후 기록 변경 | 삭제 요청 거부 |
| 자동 실행 시간 | 2초 |
| 보존 기간 시험 | 테스트 시계만 90일 전진; OCI 생성 시간을 조작하거나 실제 90일을 기다린 시험은 아님 |
| 운영 Function | 기존 이미지 digest 유지 |

삭제 검증은 저장소의 실제 이미지 ID·etag와 Functions 참조를 조회했고, 삭제 후에도 6개가 남았음을 확인했습니다. 테스트용 보존 기간 시계는 일반 실행에서 설정할 수 없습니다.

## Function 생성·사용 기록 연결 검증

같은 격리 Function에 최신 템플릿을 설치하고 새 캐시를 만들도록 빌드했습니다. 의존성 생성 27.83초, 런타임 전환 후 앱 빌드 137.05초였으며 전체 177초에 끝났습니다. 155개 테스트가 모두 통과했고 새 캐시 2개의 생성 사실·성공 사용 시점이 기록됐습니다. 최종 이미지의 실행 ID·커밋·테스트 통과·ARM64 증거도 다시 조회했습니다.

결과 digest: `sha256:f55ed114beab739797c389ddd260a993bf5adaec100028fa82bf53b2a079073f`.

전체 검증은 `./mvnw verify` 446개 중 441개 통과, 선택 실행 테스트 5개 제외, 실패/오류 0입니다. Python 11개도 통과했습니다. 실검증 테스트는 별도 환경 변수로 실행하며 위 이름의 격리 저장소·Function인지 확인한 후에만 변경합니다.

## 적용 범위와 다음 단계

운영 Function에 새 템플릿을 설치하거나 운영 캐시 자동 삭제를 켜지 않았습니다. 새 템플릿은 캐시 생성·사용 정보를 보고하며, 이 정보가 없는 기존 캐시를 추측으로 정리 대상에 넣지 않습니다. 운영 반영 시 현재 Function 이미지·설정을 백업하고 빌드가 없는 때 템플릿을 갱신한 다음, 별도 앱 빌드와 재빌드로 확인해야 합니다. 운영 Sustena 앱 배포는 필요하지 않습니다.

소스 전달 이미지·태그 없는 중간 이미지의 시간 기반 자동 정리는 이번 구현에 포함하지 않습니다. 이들은 임의 소유권 추정으로 지우지 않으며, 검증 자원만 명시적으로 정리합니다. 독립 데이터 디렉터리 간 분산 잠금과 정기 스케줄러도 남아 있습니다.
