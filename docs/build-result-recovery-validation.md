# 중복 빌드 방지와 완료 결과 복구

같은 ARM Function/VM에 빌드 요청이 겹치거나 Companion 연결이 끊겨도 불확실한 작업을 다시 실행하지 않습니다. ARM 빌드 화면에서 미확인 실행을 열고 **OCIR 완료 증거 재확인**을 누르면, 해당 실행이 만든 테스트 완료 이미지가 있을 때만 성공으로 복구합니다.

## 확인한 결과 · 2026-11-26

별도 `companion-verify-recovery-builder` Function에서 Sustena 소스 `a829ff928af94ea1275e27170fdf6b0d067429b0`를 빌드했습니다. 운영 Function은 변경하지 않았습니다.

## 사용과 한계

- 원격 실행 이후 오류는 보수적으로 UNKNOWN으로 기록합니다. 제한 시간만으로 실패/종료를 단정하지 않습니다.
- 완료 증거가 없으면 잠금을 유지합니다. 사용자가 원격 실행 종료를 직접 확인한 경우에만 **원격 종료 확인 후 실행 포기**를 사용할 수 있습니다. 이 버튼은 원격 프로세스를 중지하지 않습니다.
- 같은 데이터 디렉터리의 프로세스들 사이에서 실제 Function/VM별로 배타 실행합니다. 독립 데이터 디렉터리나 다른 호스트 사이의 분산 잠금은 아닙니다.
- 복구에는 등록된 인증 참조가 필요합니다. 일회성 토큰을 저장하거나 재사용하지 않습니다.
- 기존 Function 이미지에는 실행 증거 라벨이 없을 수 있습니다. 이번 검증은 새 템플릿을 설치한 격리 Function에서 수행했으며 운영 Function에 새 템플릿을 적용하지 않았습니다. 기존 이미지는 임의로 성공 처리하지 않습니다.

구현 원칙은 [설계 문서](design/build-recovery-cache-maintenance.md)를 참고하세요. 문서 작성 시 지식 DB의 공통 안내를 조회했지만 연결 오류로 가져오지 못했으며, 위 내용은 코드·테스트·실제 검증 기록에 근거합니다.
