# 작업 중심 빌드 UX

2026-10-27 · Redmine #1000, #1001

## 진입과 흐름

`빌드`는 `/builds/tasks`로 진입한다. 상위 탭은 빌드 작업 / 실행 이력 / 환경 관리다. OCI 프로젝트·파이프라인·Functions·Registry·알림 주제 관리는 환경 관리에 연결한다.

새 작업: 소스 → 빌드 설정 → 실행 환경 → 확인 → 저장. 저장된 작업에서 설정 확인·실행 또는 실행 이력·로그로 이동한다. 저장만으로 클라우드 빌드를 호출하지 않는다.

현재 선택 요약은 상단에 유지한다. 소스/커밋, 빌드 도구/Goal/프로파일, 실행 환경, 결과 버킷/산출물 패턴을 표시한다. 요약을 누르면 해당 단계로 돌아가며 입력은 유지된다. 모바일에서는 두 열로 표시한다. 각 항목의 `?`는 역할·적용 위치를 간략히 설명한다.

## 실행 방식

- Functions: 등록된 소스 또는 직접 Git URL, 고정 커밋, Maven 설정, 실제 애플리케이션·빌더 선택. 결과 버킷은 빌더 설정에서 가져온다. 저장한 설정이 실행 폼에 적용된다.
- OCI DevOps: 등록 소스와 기존 파이프라인 소스를 대조한다. 하나의 소스와 일치해야 저장하며, 선택한 브랜치·커밋을 실행 화면에 전달한다. 빌드 명령·저장소는 OCI 설정을 사용한다. 실행 파라미터는 기존 실행 화면에서 지정한다.
- VM: 작업 연결 미구현 표시. 실행 선택에 제공하지 않는다.

새 환경 구성은 새 창에서 열어 작성 중인 입력을 유지한다. 구성 후 목록 재조회로 연결한다. Functions와 DevOps 조회 오류는 구분한다. 글로벌 범위를 바꾼 뒤 이전 폼을 제출하면 서버에서 거부한다.

## 저장·검증

BuildTaskStore 인터페이스와 JSON 어댑터를 분리한다. 로컬 build-tasks 파일은 프로파일·사용자·테넌시·리전·구획별로 분리하며 원자적으로 교체한다. 비밀값 입력 기능은 없다. 삭제는 로컬 작업 설정만 제거한다.

자동 테스트 65개 통과. 실제 DEFAULT / ap-seoul-1 / Joungmin.Ko로 Functions와 DevOps 작업을 저장하고 실행 화면에 값이 전달되는 것을 확인했다. 단계 이동 시 값 유지, 요약, 도움말, 320/390/768/1024/1440/2048px 배치를 브라우저로 검증했다. 이번 검증에서는 빌드를 새로 실행하지 않았다.

리뷰용 저장 작업: `db-companion 검증 · Functions`, `db-companion 검증 · DevOps`.

## 남은 범위

통합 실행 이력은 현재 작업별 이력 진입 목록이다. 여러 실행기의 상태를 한 표로 집계하지 않는다. OCI DevOps 상세 편집은 기존 화면을 재사용한다. Function 프로파일 표시를 위한 최근 제출값은 세션에만 유지하며, 다른 세션의 과거 실행에는 결과 JSON에 있는 값만 표시한다. 브라우저 새로 고침 후 미저장 초안 복원은 후속 범위다.

## 등록 소스 재사용

소스 단계에서 OCI Repository·GitHub·GitLab 등록 목록을 공통으로 선택한다. URL·기본 브랜치를 채우고 브랜치·태그·커밋을 실제 조회한다. OCI는 현재 프로파일의 SDK 권한, 공개 github.com/gitlab.com은 REST API를 사용한다. 비공개 외부 저장소의 버전 조회 인증은 아직 지원하지 않는다. 브랜치·태그 각각 최대 100개, 최근 커밋 최대 50개이며 SHA 직접 입력도 가능하다.

소스 변경 시 이전 커밋을 지운다. 새 소스 등록은 새 창으로 열고, 돌아와 목록만 갱신해 작성 중인 값을 유지한다. 선택값과 도움말은 공통 요약/필드에 표시한다. 등록 소스 ID·브랜치는 기존 JSON 작업 모델에 추가하고 기존 파일을 읽을 수 있게 한다.

DevOps는 OCI repository ID 또는 정규화한 Git URL로 정확히 하나의 소스 연결을 확인한다. 실행 전에도 다시 대조한다. 파이프라인 생성·소스 설정 화면에 등록 소스를 전달하고, 선택 가능한 연결이 하나면 자동 선택한다. 빌드 스크립트 안의 임의 git clone은 자동 변경하지 않는다.

실제 DEFAULT 프로파일로 GitHub db-companion 조회, Functions 저장·실행 폼 전달, OCI build-config 저장소 등록·커밋 조회·DevOps 실행 폼 전달을 검증했다. GitHub db-companion을 OCI build-config 파이프라인 소스로 지정하면 불일치로 막힌다. 이 파이프라인의 build.sh는 GitHub 저장소의 별도 고정 SHA를 받으므로, OCI 빌드 설정 저장소의 커밋 변경과 애플리케이션 소스 변경은 구분한다. 실제 클라우드 빌드·리소스 생성은 호출하지 않았다.
