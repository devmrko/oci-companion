# NodePort와 워커 접근 규칙

배포 담당자는 Service 이름·NodePort를 지정하고 클러스터 전체의 포트 충돌을 확인한다. 워커 접근이 필요하면 별도 화면에서 출발지 IPv4 /32와 포트를 확인한 뒤 보안 규칙을 추가한다.

Deployment 입력·YAML 생성·재배포 저장은 기존 경로를 사용한다. NodePort는 기본 Kubernetes 범위인 30000–32767로 제한한다. 실제 범위를 바꾼 클러스터는 별도 지원이 필요하다. 충돌 검사는 같은 Namespace·Service의 재배포를 허용하고 다른 Service가 사용하는 포트는 차단한다. 목록 조회가 실패하면 미확인으로 표시하고 생성하지 않는다.

보안 목록 후보는 선택한 클러스터의 노드 풀 배치 서브넷에서 가져온다. 변경은 조회 → 미리보기 → 사용자 확인 → 재조회 → 변경 전 백업 → If-Match 업데이트 순서다. 새 수신 규칙만 추가하고 기존 수신·송신 규칙을 유지한다. 제거는 Companion 표시와 출발지·프로토콜·포트가 모두 일치하는 규칙만 대상으로 한다. 동시 변경이나 불확실한 응답은 자동 재시도하지 않는다.

실제 OCI 보안 규칙 변경은 검증 계획에 대해 별도 승인을 받은 뒤 수행한다. 운영 중인 NodePort·보안 규칙은 검증 대상으로 사용하지 않는다.
