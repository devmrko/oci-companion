# 준비된 VM 배포 파이프라인 실행

운영자는 선택한 리전·구획의 OCI DevOps 파이프라인을 확인하고 실행·상태 조회를 Companion에서 수행한다. 기존 환경 관리에서 `/deployments/runs`로 연결한다. 최초 범위는 Instance Group 단계 한 개로 구성된 준비된 파이프라인이다. 패키지 업로드·파이프라인 생성은 이 화면의 범위에 포함하지 않는다.

실행 전에 파이프라인·단계·환경·배포 명세를 조회하여 대상 구획을 검증하고 내용을 요약한다. 확인 화면이 발급한 일회용 티켓은 연결 계정·리전·구획·파이프라인 및 구성 지문에 묶이며 10분 후 만료한다. POST에서 다시 읽은 구성이 달라지면 실행하지 않는다. OCI 시작 요청에는 티켓을 재시도 토큰으로 사용한다. 기존 Spring CSRF 방어를 유지한다. 조회와 시작 사이 외부 OCI 변경을 원자적으로 차단하지는 못하므로 파이프라인 변경 권한은 운영 절차로 관리한다.

버전 복구는 이전 버전을 활성화하는 별도 파이프라인을 선택해 실행한다. 앱 상태 확인과 자동 복구는 배포 명세가 호출하는 릴리스 도구의 책임이며 Companion은 OCI가 보고한 실행 상태를 표시한다. 데이터베이스를 이전 상태로 되돌리지 않는다.

## 검증 결과 (2026-11-06)

전체 테스트 108개 통과. 서울 Launchpad 예제에서 화면으로 0.3.0 복구를 실행해 OCI SUCCEEDED와 에이전트 화면의 UP·0.3.0을 확인했다. 같은 화면으로 시작한 0.4.0 재배포도 OCI API SUCCEEDED 및 실제 VM UP·0.4.0을 확인했다. 최종 빌드 재시작 뒤 Edge 확장 UI가 자동화를 차단해 마지막 화면 재확인은 수행하지 못했다. 배포 실행 구성은 미리 설치된 릴리스와 인라인 명세, 단일 VM이며 패키지 업로드·초기 설치·무중단 배포는 검증하지 않았다.

## 설치 패키지 참조

후속 패키지 배포는 단일 Instance Group 단계에 Generic Artifact를 포함할 수 있다. Companion은 각 아티팩트의 구획·프로젝트와 고정 버전 참조를 검사하고 배포 확인 지문에 전체 아티팩트 구성을 포함한다. 실제 파일 무결성은 VM의 root 설정에 고정한 manifest SHA-256으로 확인한다. Terraform은 is_immutable=true 저장소를 만든다. Companion은 패키지를 다운로드하거나 root 설치 명령을 직접 실행하지 않는다.

패키지 배포 검증 (2026-11-06): 전체 테스트 109개 통과. Terraform이 만든 0.4.1 패키지 파이프라인의 대상 확인 화면, SDK로 시작한 최종 배포의 SUCCEEDED, 에이전트 화면 UP·0.4.1 및 기억 저장·조회 성공 기록을 실제 브라우저에서 확인했다. 이번 패키지 배포 시작 자체는 OCI SDK를 사용했으며 화면 시작 버튼을 통한 패키지 배포 재실행은 수행하지 않았다.
