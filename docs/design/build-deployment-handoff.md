# 성공한 빌드에서 준비된 VM 배포로 연결하기

사용자는 빌드 이력에서 성공한 실행을 고르고, 같은 파일을 사용하는 배포 파이프라인을 확인해 실행한다. Companion은 앱 코드나 Launchpad manifest 형식을 알 필요가 없다.

## 계약

빌드 상세 → 배포 파이프라인 선택 → 저장소 파일 SHA-256 대조 → 대상 확인 → 실행 직전 재검증 → 기존 배포 실행 경로를 사용한다. 빌드·전달 성공과 실제 전달된 Artifact Registry ID가 필요하다. 대상의 모든 패키지가 전달된 파일 중 하나와 SHA-256·크기가 같아야 한다. 원본과 대상 모두 선택 구획의 사용 가능한 불변 저장소여야 한다. 다른 저장소로 복사된 동일 파일도 허용한다.

웹 세션의 만료되는 일회용 확인표에 원본 빌드·파이프라인과 검증 fingerprint를 묶는다. 제출값으로 원본을 바꾸지 못한다. 실행 직전에 소스 성공 상태·파일·대상을 다시 확인한다. 파이프라인 변경 검사는 기존 배포 fingerprint 검사를 유지한다.

## 범위와 완료 기준

기존 단일 Compute Instance Group 파이프라인만 지원한다. 새 인프라 생성, 다운로드·재업로드, VM root manifest 등록은 자동화하지 않는다. OCI의 파일 hash 일치는 빌드 산출물 연결 증거이며 서명·내부 테스트 정확성·설치 성공 보장은 아니다. 기존 직접 배포·복구 경로도 유지한다.

성공·실패 빌드, 전달 실패, 변조 hash, 다른 구획, 가변 저장소, 패키지 없는 복구 파이프라인, 실행 직전 변경, 세션 범위 변경·만료·CSRF를 검증한다. 실제 OCI 조회와 화면 검증 결과는 구현 후 별도 기록한다.

## 사용 순서

1. 빌드 → 실행 이력에서 빌드와 Registry 전달이 모두 성공한 실행을 연다.
2. **이 빌드로 배포 준비**를 누른다.
3. 미리 준비한 배포 파이프라인을 선택하고 **대상 확인**을 누른다.
4. 파일 일치 결과와 대상 VM을 확인하고 **확인한 배포 실행**을 누른다.
5. OCI 배포 상태가 SUCCEEDED인지 확인한 뒤 **에이전트 상태 확인**으로 이동한다.

추가 조회 권한은 선택 구획의 Artifact Registry 저장소·파일 읽기다. 기존 DevOps·대상 VM 조회 및 배포 실행 권한도 필요하다. Companion은 IAM을 자동 확대하지 않는다. Registry의 SHA-256과 크기만 읽으며 대용량 패키지나 비밀 파일을 다운로드하지 않는다.

2026-11-07 전체 회귀 테스트 122개 통과. 실제 서울 OCI의 성공한 0.5.0 빌드와 준비된 0.5.0 배포 패키지 일치, 0.4.2 배포 패키지 불일치 차단을 확인했다. Companion 화면에서 성공 빌드 → 대상 선택 → 파일 일치 표시 → 실행 접수까지 확인했다.
