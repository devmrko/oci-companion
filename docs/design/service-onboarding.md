# 기존 설정을 읽어 새 서비스를 배포하기

이미 실행 중인 앱의 소스·클러스터를 선택하면 현재 설정을 읽어 새 이름의 서비스를 배포하고 등록하는 흐름을 추가합니다. 볼륨·프로브·pull Secret·접속 정보를 다시 입력하지 않아도 되는 것이 목표입니다.

기존 OperatingServices, OkeDeploymentInputs, OkeApiAccess, OciOkeDeploymentSetup, DeploymentOperations를 재사용합니다. 소스에 연결된 등록 서비스를 설정 근거로 선택하고, live Deployment를 조회해 실제 설정을 가져옵니다. 여러 근거가 있으면 사용자에게 선택을 요구하며 임의로 첫 번째를 고르지 않습니다. 아직 근거가 없는 소스는 상세 설정 화면으로 연결하며 확인되지 않은 값을 추측하지 않습니다.

새 Deployment의 이름·selector·Pod label은 새 이름으로 분리합니다. 기존 볼륨·보안·프로브와 digest는 보존하고, 기존 NodePort는 참고값으로만 보여 줍니다. 새 Service 기본값은 ClusterIP이며 기존 NodePort·보안 규칙을 변경하지 않습니다. Namespace 객체는 생성하지 않습니다. Secret 값은 읽거나 저장하지 않고 참조 이름만 사용합니다.

미리보기는 기존 설정과 IAM을 읽고, 생성 요청 시 같은 설정인지 다시 확인합니다. 전용 DevOps 환경(기존 네트워크 채널 설정 재사용)·pipeline·manifest·stage를 생성하고 각각 비동기 완료를 기다립니다. 신규 pipeline의 IAM도 다시 점검합니다. 권한이 부족하면 필요한 문장만 표시하고 자동 정책 생성 없이 멈춥니다. 각 단계에서 생성된 참조를 사용자 범위에 기록하여 부분 실패를 숨기거나 자동 중복 생성하지 않습니다.

최종 성공은 실제 Pod digest·Ready 확인으로 판단하고, 성공 후 조회 연결과 운영 서비스 등록을 완료합니다. 검증은 새 이름에서 수행하고 생성 자원만 삭제합니다. 이 문서는 구현 설계이며 실제 검증 결과는 별도 기록합니다.
