# 소스 또는 기존 설정으로 새 서비스를 배포하기

이미 실행 중인 앱의 소스·클러스터를 선택하면 현재 설정을 읽어 새 이름의 서비스를 배포하고 등록하는 흐름을 추가합니다. 볼륨·프로브·pull Secret·접속 정보를 다시 입력하지 않아도 되는 것이 목표입니다.

기존 OperatingServices, OkeDeploymentInputs, OkeApiAccess, OciOkeDeploymentSetup, DeploymentOperations를 재사용합니다. 소스에 연결된 등록 서비스를 설정 근거로 선택하고, live Deployment를 조회해 실제 설정을 가져옵니다. 여러 근거가 있으면 사용자에게 선택을 요구하며 임의로 첫 번째를 고르지 않습니다. 실행 중인 앱이 없는 소스는 아래 소스 기반 흐름을 사용하며 확인되지 않은 값을 추측하지 않습니다.

새 Deployment의 이름·selector·Pod label은 새 이름으로 분리합니다. 기존 볼륨·보안·프로브와 digest는 보존하고, 기존 NodePort는 참고값으로만 보여 줍니다. 새 Service 기본값은 ClusterIP이며 기존 NodePort·보안 규칙을 변경하지 않습니다. Namespace 객체는 생성하지 않습니다. Secret 값은 읽거나 저장하지 않고 참조 이름만 사용합니다.

미리보기는 기존 설정과 IAM을 읽고, 생성 요청 시 같은 설정인지 다시 확인합니다. 전용 DevOps 환경(기존 네트워크 채널 설정 재사용)·pipeline·manifest·stage를 생성하고 각각 비동기 완료를 기다립니다. 신규 pipeline의 IAM도 다시 점검합니다. 권한이 부족하면 필요한 문장만 표시하고 자동 정책 생성 없이 멈춥니다. 각 단계에서 생성된 참조를 사용자 범위에 기록하여 부분 실패를 숨기거나 자동 중복 생성하지 않습니다.

최종 성공은 실제 Pod digest·Ready 확인으로 판단하고, 성공 후 조회 연결과 운영 서비스 등록을 완료합니다. 검증은 새 이름에서 수행하고 생성 자원만 삭제합니다. 이 문서는 구현 설계이며 실제 검증 결과는 별도 기록합니다.

## 새 소스의 첫 배포

등록된 OCI 소스에서 선택 브랜치의 실제 커밋을 고정하고 archive를 읽습니다. 배포 YAML의 값, 최종 Dockerfile 단계의 EXPOSE·HEALTHCHECK, 앱 설정의 순서로 포트·프로브·복제본 수·pull Secret 이름을 찾습니다. Helm 표현식은 실행하지 않으며 미확인 값으로 표시합니다. Secret 리소스의 값은 추출·저장하지 않고 배포에 필요한 참조 이름만 사용합니다. archive 크기·파일 수·설정 파일 크기와 YAML 중첩·별칭 수를 제한합니다.

찾은 값마다 파일 경로와 필드를 미리보기에 표시합니다. 누락된 필수값만 기존 화면에서 입력받고 pull Secret은 기존 Namespace의 dockerconfigjson 이름 목록에서 고릅니다. 기존 등록 서비스는 클러스터·Namespace·사설 API 연결의 근거로만 사용하며 앱의 볼륨·환경값·이미지는 복사하지 않습니다. 다른 Namespace 이관과 신규 Secret 생성은 지원하지 않습니다.

선택한 기존 빌더로 고정 커밋을 테스트·빌드하고, 성공한 실제 digest로 공통 OKE 미리보기를 만듭니다. 사용자가 digest와 명세를 확인하면 공통 환경·pipeline·artifact 생성 및 Pod imageID 검증 흐름을 실행하고 운영 서비스로 등록합니다. 모호한 빌드 응답은 재시도하지 않도록 실행 전 티켓 소비를 저장합니다. 새 IAM이 필요하면 기존 권한 화면으로 연결하고 자동 생성하지 않습니다.

자동 추출 대상은 포트·HTTP 프로브 경로·replica·pull Secret 참조입니다. 저장소의 전체 Kubernetes 명세를 그대로 적용하지 않습니다. 볼륨·환경 변수·보안 컨텍스트 같은 고급 설정은 기존 상세 설정을 사용해야 합니다. Helm 템플릿은 렌더하지 않으며 실제 값을 확인할 수 없는 항목은 자동 확정하지 않습니다.
