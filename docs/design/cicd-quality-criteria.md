# CI/CD 품질 기준

2026-11-02 · 사용자 승인 기준. 기존 OCI 프로파일·권한, 교체 가능한 어댑터, 앱 없이 실행 가능한 명세·템플릿을 유지한다.

## 기준과 완료 조건

| 기준 | 완료 조건 | 현재 상태 | 순서 |
| --- | --- | --- | --- |
| 쉬운 기본 경로 | 소스 → 빌더 → 테스트 → 저장소 → 배포. 선택값 유지, 필수/선택 구분, 상세 설정 접기, 역할·OCI 콘솔/CLI·권한 도움말 | 부분 구현 | 1 |
| 명확한 실행 결과 | 접수·실행·저장·배포 성공 구분. 실패 단계·원인·로그·보고서·다음 조치 연결 | 빌드 로그·보고서 검증, 배포 미완료 | 1 |
| 재사용 가능한 빌드 환경 | 빌더 이미지와 배포 이미지 분리. digest·실제 도구 버전 기록. lock 파일 사용. Go/Ruby 직접 설치 없이 실행 검증 | Go/Ruby x86 빌더 실행 검증, lock 정책 후속 | 1 |
| 캐시 재사용 | 실행기별 지원 여부 확인 후 의존성/레이어 캐시 적용. 키에 도구 버전·lock 파일·아키텍처 반영. 캐시 없는 실행·삭제 제공 | 미구현 | 2 |
| 동일 산출물 배포 | 한 번 검증한 digest를 환경별로 재사용. 환경값 분리. 배포 이력에서 원본 빌드 추적 | Registry 저장 검증, 배포 연결 미완료 | 2 |
| 설정을 코드로 보관 | GUI → 명세 미리보기 → 변경 비교 → Git 저장. 소스·명세 revision 기록. 앱 없이 실행 | 빌드 명세 부분 구현 | 1 |
| 통제 가능한 자동 실행 | Push/PR/예약, 실제 발생 원인·커밋 기록. 중복 실행 정책·취소·중지. 테스트 일정 종료 후 비활성화 | OCI Push·예약 검증 완료, 외부 Webhook·PR 후속 | 1 |
| 산출물 출처·보안 | 소스 SHA·빌더 digest·설정·산출물 연결. SBOM·취약점 검사·서명 검증 결과를 별도 표시. 비밀값은 Vault/실행 시 참조 | 추적 정보 일부, 보안 검사 미구현 | 2 |
| 배포 후 확인·복구 | 상태 검사·로그·이전 digest 복원. 대상별 지원 범위 표시. 단계적 배포는 가능한 대상에서 선택 | 미구현 | 3 |

상태는 구현, 실제 검증, 미구현을 구분한다. 예제 성공을 모든 언어·아키텍처·저장소 제공자 검증으로 확대하지 않는다.

## 이번 보완 범위

1. Go/Ruby 빌더 이미지 선택, 생성 명세의 실제 OCI 실행, 결과/실패 코드·정리 확인.
2. 전용 OCI Git 브랜치 Push → 빌드 실행 확인.
3. 독립 Function → Resource Scheduler 예약 → 빌드 실행 확인. 시험 일정은 검증 뒤 중지.
4. GUI 결과와 문서·GitHub·Redmine 이력 연결.

캐시·배포·보안 검사는 후속 구현이다. OCI OL8의 Docker 호환 엔진이 Podman인 점을 고려해 BuildKit 전용 캐시를 지원한다고 가정하지 않는다. 이미지 재사용은 도구 설치를 줄이지만 최초 pull·의존성 설치 시간은 남는다.

## 설계 원칙

- 빌드: 소스 + 빌더 이미지 + 명령 + 의존성 lock → 테스트 + 산출물.
- 배포: 산출물 digest + 대상 + 환경 설정 → 상태 확인 + 운영 이력.
- 빌더에는 도구를, 배포 이미지에는 실행에 필요한 파일·런타임을 넣는다.
- OCI DevOps 실행기 이미지와 그 안에서 사용하는 빌더 컨테이너는 다른 설정이다.
- Git 저장만으로 GitOps 완료라고 하지 않는다. 자동 pull·지속적인 상태 조정이 있을 때 GitOps로 표시한다. Argo CD 같은 추가 서비스는 선택 연동으로 둔다.
- digest 기록은 서명된 출처 증명과 다르다. SLSA 등급을 실제 충족 여부 확인 없이 표시하지 않는다.
- UI는 공통 CSS 클래스로 구성한다. 도움말은 짧게, 상세 내용은 펼쳐보기로 제공한다.

## 측정

빌드 대기/실행 시간, 캐시 적중 여부, 빌드 실패율을 기록한다. 배포 구현 후 변경 리드타임, 배포 빈도, 변경 실패율, 실패 배포 복구 시간, 배포 재작업률을 추가한다. OCI 리소스 비용은 실제 사용량/가격 근거 없이 추정치를 확정값으로 표시하지 않는다.

## 근거

최근 조사와 공식 기술 문서를 앱의 수용 기준으로 정리한 것으로, 모든 항목이 하나의 공식 표준에 속하지는 않는다. 2026-11-02 확인.

- [DORA 2025 연구](https://dora.dev/research/2025/dora-report/): 사용자 중심 플랫폼과 조직의 전달 능력.
- [DORA 플랫폼 엔지니어링](https://dora.dev/capabilities/platform-engineering/): 기본 경로, 셀프서비스, 확장성, 명확한 결과 피드백.
- [CNCF 2025 조사, 2026년 공개](https://www.cncf.io/wp-content/uploads/2026/01/CNCF_Annual_Survey_Report_final.pdf): CI/CD·GitOps 활용. 조사 집단의 결과를 전체 조직에 일반화하지 않는다.
- [Docker 캐시](https://docs.docker.com/build/cache/backends/), [uv 컨테이너](https://docs.astral.sh/uv/guides/integration/docker/): 외부 캐시, 의존성 레이어 분리, digest 고정.
- [SLSA provenance](https://slsa.dev/spec/v1.2/provenance): 산출물 출처 추적.
- [OpenGitOps](https://opengitops.dev/): 선언적·버전 관리·자동 pull·지속 조정.
- [Argo Rollouts](https://argo-rollouts.readthedocs.io/en/stable/): 단계적 배포와 지표 기반 판단.
- [DORA 지표](https://dora.dev/guides/dora-metrics/): 현재 5개 전달 성과 지표.
