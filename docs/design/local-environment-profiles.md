# 환경·인증 프로파일을 로컬 JSON으로 관리하기

개발자는 환경마다 같은 값을 반복 입력하지 않고 프로파일을 선택해 필요한 항목을 채운다. 프로파일은 Companion 밖에서도 읽을 수 있는 JSON이며, 환경 값을 앱 코드에 고정하지 않는다. 이 단계는 설정 작성·보관·검증 기능이다. 저장만으로 인증이나 OCI 권한이 적용되었다고 표시하지 않는다.

## 저장 계약과 경계

- JSON schemaVersion 1, 프로파일마다 별도 파일. 기본 폴더 `.data/environment-profiles`는 `companion.environment-profiles-dir`로 변경한다. 로컬은 브라우저 PC가 아니라 Companion 프로세스가 실행되는 호스트다.
- 현재 OCI 연결의 profile·tenancy·user·demo 경계로 디렉터리를 분리한다. 설정의 target region/compartment는 명시적으로 입력하며 상단 선택값을 자동 덮어쓰지 않는다.
- 템플릿 ID와 버전, 사용자 입력 values, 이름, revision을 보관한다. 불완전한 입력도 초안 저장하고 누락 필드를 표시한다. 다른 프로파일의 값을 상속하거나 자동 채우지 않는다.
- `demo-token`, `workforce-oidc`, `service-oauth` 구성 초안을 제공한다. 인증과 인가 적용은 후속 단계다. 필드 완성을 연결 성공·배포 가능·운영 준비 완료와 구분한다.
- 비밀번호·토큰·client secret·개인 키 필드는 받지 않는다. 비밀은 `credential:<논리이름>` 또는 `vault:ocid1.vaultsecret...` 참조만 보관한다. 참조를 실제로 해결하는 기능은 아직 없다. 특정 Mac 경로나 토큰 파일을 이식 가능한 프로파일에 넣지 않는다.
- 호스트별 자격증명 바인딩은 별도 관리자 설정에서 관리할 후속 기능이다. 기존 agent-credentials.json을 자동 변경하거나 병합하지 않는다.
- 디렉터리 0700, 파일 0600, 상위 경로·파일의 symlink 거부, 크기 제한, atomic replace, 파일 잠금과 revision 충돌 검사를 적용한다. POSIX 권한 미지원 환경은 실패하며 Windows ACL 지원은 별도 작업이다.
- 내보내기는 scope 소유 메타데이터를 제외한 설정만 내려준다. OCID·issuer·조직 식별자는 여전히 민감한 환경 정보일 수 있다. 로컬 파일은 암호화 저장이 아니며 OS 계정·디스크 암호화·백업 범위는 운영자가 관리한다.

## 화면과 이번 완료 기준

환경 프로파일 목록(20개씩) → 템플릿 선택·새 프로파일 → 필수/선택 입력 → 초안 저장 → 누락/형식 확인 → JSON 내보내기/가져오기 미리보기. 템플릿은 프로파일 생성 시 고정하며 변경이 필요하면 새 프로파일을 만든다. 저장과 조회는 OCI API·IdP·Vault를 호출하지 않는다. JSON import는 256 KiB 이하의 설정 파일을 엄격하게 파싱하고 미리보기로 보여준다. 저장을 눌러야 현재 연결 주체의 새 UUID/초기 revision으로 저장하며 기존 파일을 덮어쓰지 않는다. 알 수 없는 필드, 중복 JSON 키, 다른 버전, 잘못된 자료형·참조는 거부한다. 누락 필드는 초안으로 허용한다. 기존 배포 화면의 프로파일 적용은 후속 단계다.

검증은 두 프로파일 값 분리, 다른 연결 주체 접근 거부, 누락 필드, 잘못된 값·평문 비밀 필드 거부, 오래된 revision 덮어쓰기 방지, 파일 권한·symlink·손상 파일 거부, CSRF, 웹 초안 저장/내보내기/가져오기 왕복를 포함한다.

## 이어서 적용할 단계

1. 프로파일 구조/템플릿 버전 변환, 호스트별 자격증명 바인딩.
2. 실제 OCI·IdP 사전 점검과 변경 계획. scope·profile revision·대상 자원 fingerprint를 실행 시 재검사.
3. 템플릿별 앱/인프라 설정 생성 및 적용. 기존 인증을 교체하기 전에 영향과 되돌리기 준비.
4. 유효/만료/잘못된 issuer·audience/권한 없는 사용자/다른 고객 데이터 거부 시험.

인증 설정의 기준은 [OpenID Connect Core](https://openid.net/specs/openid-connect-core-1_0.html)를 따른다. issuer·audience 입력이 완성됐다는 사실만으로 토큰 검증이 구현되는 것은 아니다. 서비스 호출용 OAuth와 사용자 로그인은 별도 템플릿으로 취급한다.

## 사용과 검증

메뉴의 **환경 프로파일**에서 템플릿을 선택하고 초안을 저장합니다. 기존 프로파일을 열면 저장본 JSON을 내려받을 수 있습니다. 가져오기에서는 파일을 선택하고 미리보기를 확인한 뒤 이름·환경 값을 수정해 저장합니다. 필수 입력 완료는 연결 검증이나 운영 인증 완료를 의미하지 않습니다.

별도 저장 위치는 실행 인수 `--companion.environment-profiles-dir=/absolute/private/path`로 지정합니다. 해당 폴더는 0700이어야 하며 부모 경로에 심볼릭 링크가 없어야 합니다. 배포 JAR는 기본 프로파일로 실행하며 `demo` Spring 프로파일은 테스트 전용 어댑터입니다.

2026-11-09 검증: Maven verify 163 tests, failures/errors/skipped 0. 프로파일 격리, 소유 범위, stale revision, CSRF, 파일 권한, 잘못된 import, export/import 왕복, 20개 페이지 구분을 포함합니다. 별도 로컬 서버 브라우저에서 로그인·초안 저장·누락 안내·JSON 다운로드를 확인했습니다. 파일 업로드 자동화는 브라우저 확장의 파일 URL 접근 설정 때문에 미확인입니다. 업로드의 서버 경로는 MockMvc multipart 시험에서 검증했습니다.

고객 인터뷰 원문과 LLM 해석은 이 파일에 추가하지 않습니다. 프로젝트 근거 저장소에서 관리하고 향후 프로파일 필드별 요구/결정 revision을 별도 provenance로 연결합니다. 현재 JSON import는 인터뷰 패키지를 받지 않습니다.
