# OCI 소스 전달과 연결 재사용

등록한 소스를 OCI 저장소로 보내고 빌드 명세를 저장할 수 있게 한다. OKE 조회 연결은 재등록해도 같은 워크로드의 연결을 하나로 유지한다.

## 소스 전달

소스 화면의 **OCI 저장소로 소스 보내기**에서 등록 소스와 대상 OCI 저장소, 브랜치, Git 인증 참조를 선택한다. 미리보기의 커밋과 대상을 확인한 뒤 새 브랜치로 push한다. 기존 JGit 전송·인증 코드를 재사용하며 HTTPS 호스트 검증을 유지한다.

대상 브랜치가 이미 있으면 중단한다. 초기 커밋이 있는 main과 이력을 강제로 합치거나 덮어쓰지 않는다. 새 브랜치를 빌드 구성에서 선택한다. 실행 전에 소스 커밋을 다시 확인하고, 원격 브랜치가 없는 조건으로 전송한다. Git LFS 객체 전송은 지원하지 않는다.

## 명세 저장과 OKE 조회 연결

파이프라인 화면에도 등록 소스 목록과 Git 저장 입력을 제공한다. OCI 저장소도 동일한 비교·확인·커밋 절차를 사용한다.

OKE 재등록 시 현재 사용자·프로파일·리전·구획 범위에서 클러스터, Namespace, Deployment가 같은 등록을 찾는다. 기존 ID를 재사용하고 새 kubeconfig와 접속 옵션으로 갱신한다. 다른 워크로드나 다른 범위의 연결은 합치지 않는다.

## 검증 범위

로컬 Git 저장소 테스트로 초기 커밋 유지와 중복 브랜치 거부를 확인한다. 연결 테스트는 재등록 ID 재사용과 범위 분리를 확인한다. 실제 OCI 결과는 배포 검증 문서에 별도로 기록한다.
