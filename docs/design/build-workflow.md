# 빌드·저장·배포 화면 설계

2026-10-27 · Redmine [#996](https://redmine.cloud-handson.com/issues/996)

상태: 설계. 구현·배포 완료 기록이 아니다.
근거: [DevOps 액션·입력값 대조](devops-action-matrix.md). 주요 21개 액션과 기본 배포 경로를 대상으로 한다.
기존 구현 기준은 58167a7. 작성 중인 실행 탭 변경은 완료 판정에서 제외한다.

## 1. 메뉴와 책임

상단의 프로파일·리전·구획을 모든 화면에 적용한다. 프로젝트는 DevOps 리소스를 묶는 OCI 리소스이며 빌드 화면에서 선택한다.
파이프라인은 소스·명령·산출물 전달 등 실행 단계의 저장된 구성이다. 실행 이력은 그 구성을 실행한 기록이다.

| 메뉴 | 탭 | 주요 작업 |
|---|---|---|
| 소스 | 저장소 / 외부 연결 | OCI 저장소 조회·생성, 외부 URL 등록, OCI Connection 연결, 브랜치·커밋 조회 |
| 빌드 | 빌드 실행 / 실행 이력 / 파이프라인 / 프로젝트 / Registry / 알림·로그 | 실행, 구성 관리, 선행 리소스 준비 |
| 배포본 | 파일 / 이미지 | 저장된 버전·digest·출처·배포 사용처, 배포 선택 |
| 배포 | 배포 실행 / 실행 이력 / 파이프라인 / 환경 | VM → Functions → OKE |
| 모니터링 | 상태 / 지표 / 로그 / 작업 이력 | 대상별 지원 작업과 로그 조회 |

Registry 탭은 저장소 관리, 배포본 메뉴는 실제 저장된 파일·이미지 관리다. 같은 저장소 선택 컴포넌트를 공유한다.
프로젝트·파이프라인 선택 즉시 상세를 조회한다. 이름만 선택하고 내용이 감춰지는 화면은 만들지 않는다.
미구현 탭은 상태를 표시하고 실행 버튼을 제공하지 않는다.

## 2. 공통 입력 규칙

- 필수: 항상 필요한 값. 선택으로 채운 ID도 상세에서 확인할 수 있다.
- 조건부 필수: 선택한 작업에 필요한 값. 조건을 필드 옆에 표시한다.
- 선택: 생략 가능. 기본값과 적용 출처를 표시한다. 조회할 수 없는 기본값은 미확인으로 표시한다.
- 앱 입력: goal·task 등 빌드 명세로 변환하는 값. 변환된 명령을 함께 표시한다.
- 기존 리소스는 검색 가능한 선택 목록. 생성 버튼은 해당 관리 탭으로 이동한다.
- 생성 후 원래 화면으로 돌아와 새 리소스를 선택한다. 입력 초안과 반환 위치를 유지한다.
- 범위 변경 시 다른 범위의 선택 ID를 해제한다. 기존 초안은 해당 범위에 남기고 자동 이식하지 않는다.
- 조회 실패와 0건을 구분한다. 캐시 조회 시각을 표시하고 변경 직전 실제 상태를 재조회한다.

## 3. 프로젝트 / 알림·로그

| 화면 | 필수 | 선택·조건 | 동작 |
|---|---|---|---|
| 프로젝트 생성 | 현재 구획, 이름, 알림 주제 | 설명 | 생성 → 상태 확인 → 상세 |
| 알림 주제 생성 | 현재 구획, 이름 | 설명 | 주제 생성 후 프로젝트 폼으로 복귀 |
| 알림 구독 | 주제, 프로토콜에 맞는 수신 대상 | 확인이 필요한 구독의 확인 상태 | 구독 관리·확인 안내 |
| 프로젝트 로그 | 로그 그룹, 이름, DevOps 프로젝트, 서비스 로그 구성 | 보관 설정 등 지원 필드 | 기존 로그 선택 또는 생성·활성화 |

프로젝트 상세: 이름·OCID·상태·주제·로그 활성화·파이프라인 목록.
알림 주제는 이벤트 통지, Logging은 실행 로그 저장·검색이다. 구독이 없으면 수신자 없음으로 표시한다.
프로젝트 생성과 로그 준비를 별도 상태로 표시한다. 주제만 있다고 실행 준비 완료로 판정하지 않는다.
알림 구독·로그 생성의 세부 필드는 해당 서비스 모델을 추가 대조한 후 구현한다.

## 4. 소스 / 외부 연결

| 구분 | 입력 | 검증·저장 |
|---|---|---|
| OCI 저장소 생성 | 프로젝트·이름·저장소 유형 필수, 기본 브랜치·설명 선택 | OCI Repository 생성. 유형별 추가 조건 검사 |
| 외부 URL 등록 | 공급자·주소·표시 이름 | 로컬 등록. 빌드 연결 완료로 표시하지 않음 |
| 외부 연결 | 프로젝트·공급자·인증 참조 | OCI Connection. GitHub PAT는 Vault secret OCID 사용 |
| 빌드 소스 선택 | 소스 이름·유형·저장소/연결·브랜치 | Managed Build의 소스 목록에 저장 |
| 소스 버전 | 조회 가능한 브랜치·커밋 선택 | 공급자별 지원 범위와 조회 실패 표시 |

GitHub부터 연결 폼을 구현한다. GitLab·자체 호스팅은 해당 공급자 모델·접속 조건을 따로 대조한다.
URL 등록만 가능한 공급자를 빌드 가능한 공급자로 표시하지 않는다.
Vault에 secret이 없으면 콘솔의 생성 위치·필요 권한을 안내하고 새로 조회한다. 비밀 문자열을 프리셋에 저장하지 않는다.
명세 저장소와 앱 저장소가 다르면 둘 다 표시한다. 스크립트 내부 checkout은 정적 분석 가능 범위만 표시한다.
스크립트가 별도 커밋을 고정하면 명세 저장소 브랜치 변경이 앱 소스 변경인 것처럼 표시하지 않는다.

## 5. 파이프라인 탭

목록 → 상세 → 편집. 상세에는 단계 순서, 소스, 명령, 저장소, 기본 파라미터, 최근 실행을 표시한다.
파이프라인 생성 필수값은 프로젝트다. 앱에서는 식별하기 위한 이름도 입력받는다.
빈 파이프라인은 `단계 없음`으로 표시하고 실행을 차단한다.

단계 추가 목록: Managed Build / Deliver Artifacts / Trigger Deployment / Wait.
선행 단계는 목록에서 선택한다. 최초 단계의 API 표현은 어댑터가 변환한다.
순환·다른 파이프라인 참조·끊긴 연결을 저장 전에 검사한다.

| 단계 | 필수·조건부 필수 | 선택·기본값 |
|---|---|---|
| Managed Build | 소스 목록, 빌드 이미지, 선행 단계, 유효한 빌드 사양 | 주 소스, 명세 경로, runner 구성, 제한 시간, 사설 네트워크 |
| Deliver Artifacts | 앞선 빌드 출력 이름과 산출물 참조 매핑, 선행 단계 | 이름·설명 |
| Trigger Deployment | 배포 파이프라인, 전체 파라미터 전달 여부, 선행 단계 | 이름·설명 |
| Wait | 대기 기준·시간, 선행 단계 | 이름·설명 |

Managed Build 신규 생성과 기존 단계 수정을 동일 폼으로 지원한다.
기존 명세의 지원하지 않는 구문은 보존한다. 자동 변환이 불가능하면 원문 편집으로 전환하고 손실 변환을 막는다.
파라미터 필수 여부·선택지는 OCI에서 알 수 있는 범위와 로컬 입력 규칙을 구분한다. 임의 추정하지 않는다.

## 6. 빌드 실행 탭

```text
프로젝트 [선택] [생성]   파이프라인 [선택] [생성] [상세]
목적     [빌드·테스트만 / 빌드·저장 / 빌드·저장·배포]

소스       저장소 · 브랜치 · 커밋 · 명세 경로
빌드       도구 · 작업 경로 · 명령 · 환경 · 출력
저장       출력별 Registry · 경로/이미지 · 버전/태그
배포       대상 파이프라인 · 환경 · 파라미터 전달
준비 상태  누락 · 오류 · 권한 · 로그 · 변경 여부

[변경 검토·저장] [실행 확인]
```

목적은 명시적으로 선택한다. 기존 단계에서 제안할 수 있지만 조용히 저장·배포 단계를 추가하거나 제거하지 않는다.
`빌드·테스트만`이어도 기존 Deliver/Trigger 단계가 남으면 그대로 실행된다. 목적과 실제 단계가 다르면 구성을 수정하거나 별도 파이프라인을 선택하도록 차단한다.

### 6.1 도구 입력

| 도구 | 선택·입력 항목 | 생성 명령 예시 |
|---|---|---|
| Maven | wrapper/Maven, JDK, goal 목록, profile, 속성, 테스트 옵션 | `./mvnw verify -Pci` |
| Gradle | wrapper/Gradle, JDK, task, 프로젝트 속성 | `./gradlew build` |
| Python | Python, 설치 방식·의존성 파일, 테스트 명령, 패키지 명령 | `pytest --junitxml=reports/tests.xml` |
| JavaScript/TypeScript | Node, npm/pnpm/yarn, lockfile, 설치·test·build script | `npm ci`, `npm run build` |

선택 목록은 저장소에서 확인한 wrapper·profile·task·script와 검증된 템플릿을 사용한다. 직접 입력도 제공한다.
도구 감지 실패는 선택을 요청한다. 모든 프로젝트가 같은 goal·script를 제공한다고 가정하지 않는다.
런타임 버전은 runner 지원 여부와 설치 명령을 확인한다. 위 명령은 예시이며 자동 적용값이 아니다.
작업 경로·설치·테스트·패키징 명령을 순서대로 표시한다. 추가 옵션과 셸 구문을 구분해 명령 생성 시 안전하게 인용한다.

일반 환경 변수와 Vault secret 참조를 분리한다. 파이프라인 파라미터, 명세 변수, exported variable의 출처를 표시한다.
실행 인자는 명세가 실제 참조하는 값에만 영향을 준다. goal 입력을 실행 인자로 받으려면 명세에 대응 변수를 먼저 구성한다.

### 6.2 빌드 명세 저장

빌드 명세는 version/component/steps 및 선택한 출력 정의를 갖춘 실제 YAML이다.
화면 입력 → 생성 명세·기존 명세 차이 → 저장할 저장소·브랜치·경로 선택 → 명시적 저장 작업 → OCI에서 읽을 버전 확인.
소스 수정은 별도 동작이다. 외부 Git 쓰기 미지원이면 명세 다운로드·커밋 안내 후 재조회한다.
로컬 JSON 저장만으로 OCI 빌드에 반영됐다고 표시하지 않는다.
기본 명세 경로 `build_spec.yaml`과 주 소스를 표시한다. 여러 소스의 경우 명세를 읽는 소스를 명시한다.

### 6.3 산출물 저장

`빌드·저장`과 `빌드·저장·배포`에서는 아래 표를 필수로 입력한다. 출력은 여러 개 등록할 수 있다.

| 입력 | 파일 | 컨테이너 이미지 |
|---|---|---|
| 빌드 출력 | 이름, BINARY, 빌드 결과 위치 | 이름, DOCKER_IMAGE, 로컬 이미지 식별자 |
| 저장소 | Artifact Registry 목록에서 선택·생성 | Container Registry 목록에서 선택·생성 |
| 저장 위치 | artifact path, version | repository 기반 image URI, tag |
| DevOps 참조 | GENERIC_FILE 참조 선택·생성 | DOCKER_IMAGE 참조 선택·생성 |
| 전달 연결 | 출력 이름 → 참조 ID | 출력 이름 → 참조 ID |

출력 위치와 저장소 경로를 별도 필드로 둔다. 저장소 생성·참조 생성·전달 단계 연결의 결과를 각각 표시한다.
변수 치환 모드는 명시적으로 선택한다. `${VAR}`는 정의 출처와 해석 결과를 표시한다.
런타임 exported variable은 실행 전 값 확정이 불가능하므로 `실행 시 결정`으로 표시하고 완료 후 실제 값을 확인한다.
미정의 변수는 차단한다. 불변 저장소의 고정 버전 충돌은 차단하고 고유 버전을 요구한다.
사전 충돌 조회는 예약이 아니다. 실행 중 충돌도 전달 실패로 처리한다.
기존 참조를 바꾸면 다른 파이프라인에도 영향이 갈 수 있다. 기본 흐름은 새 참조 생성 후 선택한 매핑만 변경한다.
변경하지 않은 출력 연결은 보존한다.

### 6.4 이번 실행과 저장 구분

| 값 | 저장 위치·적용 범위 |
|---|---|
| 실행 이름·지원하는 커밋 선택·실행 인자 | CreateBuildRun, 이번 실행 |
| 소스 목록·명세 경로·runner·단계 연결 | OCI 파이프라인 구성, 이후 실행에도 적용 |
| 파라미터 기본값 | OCI 파이프라인, 이후 실행에도 적용 |
| 명령·출력 정의 | Git의 빌드 명세/스크립트 |
| Registry 목적지 | DevOps 산출물 참조·Deliver 단계. 실행 API에 직접 넘기는 필드 없음 |
| 프리셋·입력 규칙·초안 | 로컬 JSON. OCI 변경과 별도 |

`변경 검토·저장`에서 Git 변경과 OCI 변경을 각각 표시한다. 반영 확인 전 실행을 막는다.
`실행 확인`에는 적용 소스 버전, 명령, 출력·저장 위치, 배포 여부, 실행 인자와 미확인 조건을 표시한다.
실행 확인 후 중복 제출 방지 토큰으로 제출한다. 새 실행은 실행 이력 상세로 이동한다.

## 7. 실행 전 검증과 실패 처리

| 항목 | 판정 |
|---|---|
| 범위·리소스 상태·단계 그래프 | 실제 조회. 변경·삭제·비활성·다른 소속이면 차단 |
| 소스·명세 | 연결, 명세 존재·구조, 지원 가능한 소스 버전 확인 |
| 저장 | 목적에 맞는 출력·참조·전달 연결, 유형 일치, 변수 정의·버전 충돌 확인 |
| 배포 | Trigger 단계와 대상 파이프라인·환경·산출물 연결 확인 |
| 로그 | DevOps 프로젝트 로그 활성화 확인. 누락이면 준비 화면 연결 |
| 권한 | 사용자 조회/수정 권한과 파이프라인 실행 권한을 별도 표시 |

결과 상태: 확인 / 누락 / 오류 / 권한 확인 필요 / 실행 시 확인.
확정된 필수 누락·오류는 차단한다. 읽기 권한으로 실행 권한 전체를 증명하지 않는다.
검증 불가능한 서비스 권한은 도움말과 함께 실행 확인에 남긴다. 실제 API 실패가 최종 판정이다.
NotAuthorizedOrNotFound 등 모호한 응답을 권한 부족 또는 삭제로 단정하지 않는다.

저장 순서: 명세 버전 확인 → 필요한 참조 생성 → 단계 생성·수정 → 비동기 작업 완료 확인 → 단계 그래프 재조회 → 실행 허용.
ETag 지원 작업은 동시 수정 충돌을 검사한다. 충돌 시 재조회·차이 비교 후 다시 저장한다.
부분 실패 시 성공한 리소스 ID와 실패 지점을 표시한다. 생성한 참조가 연결되지 않아도 자동 삭제하지 않는다.
응답 유실은 `결과 확인 중/불명`으로 기록한다. 요청 ID·work request·실제 리소스로 조정하고 무조건 재생성·재실행하지 않는다.
API가 지원하는 작업에서만 retry token을 사용한다.

## 8. 실행 이력 / 로그 / 결과

목록: 실행명, 파이프라인, 커밋, 시작·종료, 상태, 저장·배포 결과.
상세 탭: 단계 / 로그 / 산출물 / 테스트 / 실행값.

- 단계: 실제 OCI 단계별 상태·소요 시간·실패 이유. 단계 없는 성공 응답을 정상 빌드 완료로 인정하지 않는다.
- 로그: 실행·단계·시간 범위, 페이지 조회, 열린 화면 자동 갱신. 수집 지연·미수집·권한 실패·0건 구분.
- 산출물: Registry의 실제 파일/이미지, 버전·digest·크기 등 조회 가능한 값. 전달 실패와 빌드 성공을 구분.
- 테스트: 지원 보고서의 실제 결과만 집계. Maven test goal만으로 테스트 수를 만들지 않는다.
- 보고서: 출력·전달 설정에서 보관 위치를 지정하고 조회한다. 보고서 없음/파싱 미지원은 로그 링크 제공.
- 취소: 실행 ID·현재 상태·사유 확인 후 OCI 취소 호출. 요청 수락과 최종 취소를 구분.

## 9. 배포 연결과 후속 메뉴

| 순서 | 배포 환경 필수 | 배포 단계 필수 |
|---|---|---|
| VM | 프로젝트, 인스턴스 그룹 선택 조건 | 환경, 배포 명세 참조, rollout policy, 선행 단계 |
| Functions | 프로젝트, 함수 | 환경, 이미지 참조, 선행 단계 |
| OKE | 프로젝트, 클러스터 | 환경, manifest 참조 목록, 선행 단계 |

배포 파이프라인을 준비한 뒤 빌드의 Trigger Deployment에서 선택한다. VM agent·접속·실행 권한 등 대상별 선행 조건은 구현 전에 추가 대조한다.
전체 파라미터 전달 여부를 명시하고 대상 변수와 충돌을 확인한다.
네트워크는 대상별 VCN·서브넷·NSG·접속 경로를 연결한다. 백업은 대상·정책·배포 전 수행 여부와 실패 시 중단 규칙을 별도 구성한다.
임시 워크로드는 허용 리전·shape·체크포인트·결과 보관·회수 시 정책을 연결한다. 용량 응답을 배포 성공 보장으로 표시하지 않는다.
모니터링 작업은 대상의 실제 지원 액션만 제공한다. Functions·OKE에 VM식 start/stop을 일괄 적용하지 않는다.
Canary/Blue-Green/Helm/승인/Shell 및 상세 네트워크·백업 API는 후속 명세 범위다.

## 10. 도움말과 인터페이스

각 생성·수정·실행 화면에 `OCI에서 수행`을 둔다.
내용: 콘솔 메뉴 경로 → 현재 작업 절차 → CLI와 입력 JSON → 필수·조건부·선택 값 → 사용자/서비스 권한 → 오류·완료 확인 → 공식 문서.
목록 화면에는 list, 생성 폼에는 create, 수정 폼에는 update, 실행 화면에는 build-run create를 대응시킨다.
권한 안내는 선택한 작업의 최소 정책 예시와 OCI 콘솔 적용 위치를 제공한다. 앱이 자동으로 권한을 추가하지 않는다.
프로파일·리전·리소스 ID를 안전하게 인용한다. 비밀 값은 출력하지 않는다.

기존 BuildAdministration / BuildSetup / BuildControl / Registry 포트를 확장한다.
SourceProvider, BuildSpecService, PreflightService, OperationStore는 추가 설계 경계다. SDK 타입은 어댑터 내부에 둔다.
액션 정의에는 action ID, 필드·조건·기본값 출처·저장 대상·검증·Console/CLI 매핑을 둔다. 폼·서버 검증·도움말이 같은 정의를 참조한다.
언어별 BuildRecipe는 사용자 입력을 명세로 변환한다. OCI 클라이언트나 로컬 저장 구현을 포함하지 않는다.

로컬 JSON은 설정·프리셋·캐시·작업 기록을 분리한다. 키는 프로파일+tenancy+user+region+compartment에 프로젝트/파이프라인 ID를 더한다.
외부 URL 등록의 범위는 기존 소스 설계를 유지한다. 실행 로그·비밀 문자열은 영속 프리셋에서 제외한다.
스키마 버전·원자적 교체·범위별 직렬 쓰기를 적용한다. OperationStore는 캐시와 분리하고 응답 유실 조정 정보를 보존한다.
이 작업 기록 저장소는 신규 설계이며 현재 구현 완료로 간주하지 않는다. 다중 프로세스 운영은 별도 저장 어댑터가 필요하다.

## 11. 구현 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 프로젝트·알림·로그·소스 연결 | 필요한 리소스가 없는 환경에서 생성·복귀·실제 조회 |
| 2 | Managed Build 생성·편집, 도구·명세 | 저장된 실제 명세와 화면 명령 일치, 기존 명세 손실 없음 |
| 3 | 실행 화면 저장소·전달 연결·검증 | 파일/이미지 저장 흐름과 테스트 전용 흐름 모두 실제 실행 |
| 4 | 실행 이력·로그·취소·보고서 | 실제 단계·Registry 결과·지원 보고서로 성공 판단 |
| 5 | VM 배포 연결 | 저장된 동일 배포본으로 배포·상태·로그 확인 |
| 6 | Functions → OKE, 추가 단계·트리거 | 대상별 명세·권한·실제 서비스 검증 후 활성화 |

필수 시나리오:

1. 기존 파이프라인 선택만으로 소스·명령·저장소·기본값 확인.
2. 비어 있는 프로젝트에서 Managed Build와 파일 전달 단계를 생성해 Registry 저장까지 확인.
3. 이미지 출력 → OCIR 실제 digest 확인. 저장소만 생성된 상태는 실패/미완료.
4. 테스트 전용 실행에서 저장 생략 명시. 기존 전달/배포 단계가 있으면 목적 불일치 차단.
5. 출력 이름 불일치·미정의 변수·불변 버전 충돌은 실행 전 차단.
6. 권한 부족·로그 비활성·일부 조회 실패를 빈 목록이나 준비 완료로 표시하지 않음.
7. 동시 수정·부분 저장 실패·응답 유실에서 중복 리소스·중복 실행 방지.
8. 범위 변경·새로고침·프리셋 복원 시 다른 구획의 ID가 실행 요청에 섞이지 않음.
9. 320/390/768/1024/1440/2048 너비에서 공통 CSS·라벨·버튼·표 정렬 확인.

단일 db-companion 성공만으로 전체 흐름 완료를 판정하지 않는다. 설계 검토와 실제 OCI 검증 결과를 별도 기록한다.
