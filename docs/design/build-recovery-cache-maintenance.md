# 빌더 충돌 방지와 재시작 후 결과 확인

같은 Function의 의존성 런타임을 두 빌드가 동시에 바꾸지 않도록 실제 빌더별로 실행을 잠급니다. Companion이 중단돼도 결과가 불분명한 작업의 잠금을 임의로 해제하지 않고, OCIR에 남은 실행 증거로 결과를 다시 확인합니다.

## 완료 조건

- 같은 데이터 디렉터리를 사용하는 프로세스들은 등록 이름·사용자·프로필이 달라도 같은 실제 Function/VM을 동시에 실행하지 못합니다. 다른 빌더의 병렬 실행은 유지합니다.
- 잠금 기록은 원격 실행 전에 저장합니다. 재시작이나 통신 오류로 결과가 불명확하면 새 빌드를 막습니다. 시간 경과만으로 실행이 종료됐다고 판단하지 않습니다.
- 재확인은 빌드를 재실행하지 않습니다. 이미지의 실행 ID·소스 커밋·테스트 성공 표시·ARM64 플랫폼을 확인하고 digest를 고정한 조회로 성공을 복구합니다. 기존 이미지나 다른 실행의 이미지는 성공 근거로 쓰지 않습니다.
- 불확실한 작업은 원격 실행 종료를 확인한 사용자가 명시적으로 포기할 수 있습니다. 포기는 성공/실패 판정이나 원격 프로세스 중지가 아니며 별도 상태로 기록합니다.
- 비밀번호를 대기열이나 실행 기록에 저장하지 않습니다. 첫 단계에서는 같은 빌더의 추가 요청을 설명과 함께 거부하며, 자동 대기열은 도입하지 않습니다.

## 재사용과 검증

기존 ArmBuilds·FunctionImageBuilds·BuildSpecDraftStore와 원자적 로컬 저장을 재사용합니다. OS 파일 잠금은 실행 중 충돌을 막고, 비공개 지속 기록은 재시작 후의 불확실성을 보존합니다. 서로 다른 호스트/데이터 디렉터리의 Companion까지 분산 잠금을 제공하지는 않습니다.

별도 검증 빌더로 동시 시작 거부, 재시작 후 증거 재확인, 잘못된 증거 거부를 검증합니다. 운영 앱과 기존 IAM·보안 규칙·Secret은 변경하지 않습니다. 이후 캐시 사용 기록과 정리도 같은 잠금 안에서 수행하고 현재 참조·복구용 이미지와 최근 사용 캐시를 보호합니다.
