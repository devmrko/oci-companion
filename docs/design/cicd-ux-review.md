# CI/CD 첫 사용 UX 점검

2026-10-27 · 사용자 요청 · Redmine [#1003](https://redmine.cloud-handson.com/issues/1003)

목표: Jenkins·AWS CodePipeline 사용자가 이해할 수 있는 소스→빌드→산출물→자동 실행→결과 흐름. OCI의 실제 서비스 모델과 권한 경계는 유지한다. 이 문서는 첫 점검 기록이며 사용자 사용성 검증 완료를 뜻하지 않는다.

## 비교 기준

[Jenkins 시작 안내](https://www.jenkins.io/doc/book/pipeline/getting-started/)는 소스에 둔 Jenkinsfile, 필드별 도움말, Build History와 Console Output 진입을 제공한다. [AWS CodePipeline 생성](https://docs.aws.amazon.com/codepipeline/latest/userguide/pipelines-create.html)은 소스·빌드·배포 단계를 구성한다. [트리거](https://docs.aws.amazon.com/codepipeline/latest/userguide/pipelines-triggers.html)는 소스 액션 조건으로 관리한다.

이 구조를 기준으로 다음을 점검한다. 다른 제품의 명칭·지원 기능을 OCI에 그대로 적용하지 않는다.

| 시나리오 | 현재 판정 | 반영/후속 |
|---|---|---|
| 등록 소스로 새 빌드 시작 | 확인 | URL·브랜치·SHA 자동 연결, 선택값 요약 |
| 빌드 도구를 선택해 명령 이해 | 부분 | 네 도구 명세 생성·wrapper/system·환경 변수. 런타임 선택은 후속 |
| 프로젝트·파이프라인 의미 이해 | 첫 개선 | 생성 흐름 링크와 짧은 접기 도움말. 현업 사용자 확인 필요 |
| 없는 리소스 생성 후 원래 작업 복귀 | 부분 | 새 창·재조회·초안 유지 확인. 인라인 생성과 재시작 후 복원은 후속 |
| 테스트만/파일 저장/이미지 저장 구분 | 부분 | 출력·Registry·전달 역할 안내. 통합 입력 단계가 필요 |
| 자동 실행 설정 위치 찾기 | 확인 | 독립 상위 탭과 작업/실행 상세 링크 |
| 수동 고정 SHA와 자동 최신 버전 구분 | 첫 개선 | 자동 실행 화면에 적용 규칙 표시. 스크립트 내부 checkout은 별도 |
| 외부 Webhook 연결 완료 여부 이해 | 부분 | 생성 결과의 URL·Secret 설정 단계. 이벤트 수신 확인 기능은 후속 |
| 예약 시간 해석 | 확인 | UTC 명시, 한국시간 포함 3회 미리보기 |
| 실행 상태·로그·산출물 확인 | 부분 | 기존 실제 조회 연결. 테스트 보고서 통합은 후속 |
| 오류에서 다음 행동 찾기 | 부분 | 권한/조회 실패/없음 구분, OCI 메뉴·CLI 안내. 작업별 정책 예시 보완 필요 |
| 좁은 화면·도움말 배치 | 확인 | 여섯 화면 폭, 긴 도움말 CSS 수정, 도구와 무관한 필드 숨김 |

## 다음 사용성 과제

신규 사용자가 다음 세 작업을 별도 설명 없이 수행하는지 관찰한다. 완료율·잘못 선택한 값·되돌아간 화면·도움말 사용 위치를 기록한다. 자동 브라우저 테스트를 사람 대상 사용성 테스트로 대체하지 않는다.

1. 기존 GitHub 소스로 테스트용 빌드를 구성하고 로그 찾기.
2. JAR 저장소를 지정하고 저장된 버전 찾기.
3. 평일 오전 9시 예약을 구성하고 중지하기.

관찰 전에 선행 기능인 소스/명세 저장 연계, 실행 환경 준비, 테스트 결과 집계를 마무리한다. #1003은 진행 상태로 유지한다.
