# Public Alpha 지원 범위

2026-11-10. 개인 컴퓨터에서 OCI API 키 프로파일로 실행하는 초기 버전입니다. macOS/Linux·JDK 21 이상을 대상으로 합니다. 공유 서버·외부 네트워크 공개·운영 무중단 배포는 지원 범위가 아닙니다.

## 검증한 흐름

- 프로파일 연결, 리전·구획 선택, 소스 등록, 실제 OCI 리소스 조회.
- OCI 빌드 실행·이력·로그·산출물 전달. 언어별 범위는 예제와 검증 문서를 참고하세요.
- 준비된 VM 환경의 배포·로그와 CPU·메모리 변경·복원.
- OKE 새 구성 실행·상태·로그·v2 → v1 복구. [실검증](../validation/oke-live-2026-11-09.md).
- 사설 OCIR 빌드 → OKE 배포 → 실제 HTTP 응답·digest 일치. [실검증](../validation/private-container-flow-2026-11-10.md).
- Container Instances 공개 이미지 생성·HTTP 상태·로그·중지·시작·재시작·삭제. [실검증](../validation/container-live-2026-11-09.md).
- 별도 폴더와 빈 데이터에서 실행 ZIP 기동·프로파일 연결·조회.

단위 테스트 통과, API 요청 접수, 실제 앱 정상 응답을 구분합니다. 개발자의 계정에서 확인한 결과이며 모든 테넌시 권한 조합을 보장하지 않습니다.

## 실험 기능·알려진 제한

| 기능 | 구현·검증 상태 |
| --- | --- |
| 이미지·명세 아키텍처 | 프로파일로 사설 OCIR 플랫폼 조회, nodeSelector 불일치 차단 실검증. 실제 노드·스케줄링은 별도. [기록](../validation/image-architecture-2026-11-10.md) |
| 새 OKE 구성 | 이미지·사양·YAML·OCI 저장·실제 배포 성공 검증. 실행 주체 IAM과 이미지 인증은 별도 준비 |
| 이전 배포 복구 | 화면에서 실제 v2 → v1 복구·리소스 로그 확인. 데이터베이스·파일 데이터의 복원은 별개 |
| Container Instances | 공개 digest 이미지의 생성·정상 실행·운영·삭제 검증. 사설 OCIR은 조건부 읽기 policy 적용 후 amd64 이미지 실행·HTTP 정상·로그 확인. [검증 기록](../validation/container-pull-policy-2026-11-10.md). 외부 Vault 인증 이미지 실행은 미검증 |
| 영구 스토리지 | 기존 PVC·fsGroup 설정, 비루트 파일 쓰기·Pod 교체 후 데이터 유지 검증. 일반 파일의 블록 백업·복원은 별도 검증. DB 일관성 복원은 미검증 |
| 블록 볼륨 백업·복원 | 화면에서 전체 백업·새 볼륨 복원, 4MiB 파일 해시 일치 검증. 증분 백업은 SDK 연동·단위 검증 범위. 부트 볼륨은 콘솔 사용. 정기 정책 연결·교체·해제는 별도 탭 지원 |
| VM 볼륨 확장 | 화면에서 검증 블록 볼륨 50→51GB 확장 성공. OKE CSI의 ext4 확장·파일 유지 검증. 일반 VM의 수동 OS 확장은 미검증 |
| 신규 사용자 사용성 | 자동 브라우저 검증 수행. 외부 신규 사용자의 전체 흐름 검증은 남음 |

실험 기능은 전용 검증 환경에서 사용하세요. `예정` 메뉴는 구현되지 않았습니다. 생성·빌드·실행에는 OCI 비용이 발생할 수 있습니다.

## 설치·업데이트

릴리스 ZIP: JDK 21 이상과 `~/.oci/config`의 API 키 프로파일을 준비하고 압축을 푼 폴더에서 `./run.sh`를 실행합니다. 기본 주소는 http://127.0.0.1:8091 입니다. GitHub CLI·비공개 Foundation 저장소 접근은 필요하지 않습니다.

소스: `./scripts/build.sh` → `./scripts/run.sh`. 공개 Maven 의존성을 내려받습니다.

로컬 설정·참조·캐시는 `.data/catalog`, 등록 앱 설정은 기본 `.tools`에 있습니다. 업데이트 전 앱을 종료하고 두 폴더와 별도로 지정한 설정 경로를 백업하세요. 기존 설치 폴더에서 JAR를 교체하는 방법을 권장합니다. OKE 연결은 kubeconfig의 절대 경로를 저장하므로 설치 폴더를 옮기면 연결을 다시 저장해야 합니다. 문제가 있으면 이전 JAR와 보존한 데이터를 함께 사용하세요. 이는 OCI 리소스의 롤백이 아닙니다. 여러 프로세스가 같은 데이터 폴더를 동시에 사용하면 안 됩니다.

OKE 상태·Pod 로그 조회에는 앱 서버의 OCI CLI와 kubectl이 필요합니다. `COMPANION_OCI_CLI`, `COMPANION_KUBECTL`에 실행 파일의 절대 경로를 지정하고 실행하세요. OKE 조회 연결 화면에서 파일·실행 권한을 확인합니다. 인증·API 네트워크·RBAC 성공을 의미하지는 않습니다.

OKE 공인 API 접속은 실제 검증했습니다. 사설 API 접속과 실제 RBAC 권한을 제거한 상황은 미검증입니다. 권한 오류 처리는 자동 테스트 범위이며, 사용자 클러스터의 권한을 변경해 시험하지 않았습니다.

## 권한·실패 처리

앱은 프로파일 권한으로 SDK를 호출하며 IAM 권한을 자동 확대하지 않습니다. 화면 도움말의 OCI 콘솔 위치에서 필요한 프로젝트·구획 범위로 관리자가 설정해야 합니다. 사용자 권한과 DevOps·노드·Container 리소스 주체의 권한은 별개입니다.

응답이 불명확한 생성·실행 요청은 이력과 OCI 상태를 확인한 후 재실행하세요. 권한 오류를 해결하려고 무조건 tenancy 전체 관리 권한을 부여하지 마세요.

문제 신고에는 재현 단계·버전·오류 코드를 포함하세요. 키·토큰·프로파일 원문·`.env`·개인 캐시·민감한 빌드 로그는 첨부하지 마세요.

## 정기 백업 정책

백업·복구 → 정기 정책에서 Oracle 제공 정책과 선택 구획의 정책을 조회하고 블록 볼륨에 연결·교체·해제합니다. 일정 실행은 OCI가 담당합니다. 정책 작성·수정, 그룹 정책과 리전 간 복사는 콘솔에서 관리합니다. [실검증 기록](../validation/backup-policies-2026-11-09.md).

## alpha.5 반영

백업 이력의 생성 방식·만료·보호 정보와 볼륨별 필터, 조회 실패 시 도움말, 빌드·배포 오류 복귀를 보완했습니다. 범위 적용 후 빌드 설정·새 명세 작성·등록 앱 상태 화면을 유지합니다. Java 219개와 독립 ZIP의 실제 OCI 10개 화면을 검증했습니다. [실검증 기록](../validation/scope-navigation-alpha5-2026-11-09.md).

## alpha.6 반영

빌드 로그 조회 실패 시 이전 로그·마지막 성공 시각을 표시하고 자동 갱신을 중지합니다. 보고서 목록·본문 조회 중 선택을 바꾸면 이전 응답을 무시하며, 조회 실패와 빈 결과를 구분합니다. [로그 검증](../validation/build-log-failure-2026-11-09.md), [보고서 검증](../validation/report-content-selection-2026-11-09.md).

[독립 ZIP · 소스→빌드→VM 배포 검증](../validation/alpha6-flow-2026-11-10.md)

## alpha.7 반영

배포 재시도 시 원본 빌드 선택·산출물 검증을 유지합니다. 배포 전 점검표에 확인·미확인을 구분하고, 없는 OCIR digest와 이미지·명세의 x86/ARM 불일치를 실행 전에 차단합니다. 사설 OCIR 조회는 OCI 프로파일을 사용합니다. 실제 노드·스케줄링·네트워크 연결 성공은 별도 확인입니다. Container Instances 사설 이미지 인증·동적 그룹 한도 해결 안내도 추가했습니다.

[재시도](../validation/deployment-retry-2026-11-10.md), [점검표](../validation/deployment-preflight-2026-11-10.md), [이미지 digest](../validation/deployment-images-2026-11-10.md), [아키텍처](../validation/image-architecture-2026-11-10.md).

[alpha.7 독립 ZIP 설치·업데이트 검증](../validation/alpha7-package-2026-11-10.md): Java 230개, 실제 OCI 화면 10개와 사설 이미지 아키텍처 조회, alpha.6 데이터 복사본의 소스·범위 유지 확인.

## alpha.8 반영

OKE 조회 연결을 화면에서 생성·수정·해제합니다. 현재 프로파일로 클러스터·namespace·Deployment를 조회하고 Pod·할당 노드 상태, 노드 아키텍처, 해당 Pod의 경고 이벤트를 확인합니다. Pod·컨테이너를 선택해 현재/직전 실행 로그를 조회합니다. 로그는 최대 500줄·64KiB이며 장기 보관이나 실시간 스트리밍 기능이 아닙니다.

배포 이력에서 동일 클러스터의 등록 앱 상태·로그로 이동합니다. 현재 연결 기준이며 과거 배포 당시 앱 버전과 동일하다는 보장은 아닙니다. 연결 해제는 로컬 설정과 해당 kubeconfig만 삭제하며 클라우드 앱은 유지합니다.

OKE 도구 경로·실행 권한 안내, `.data`와 `.tools` 보존 안내를 추가했습니다. 네트워크 허용 호스트는 명시적으로 설정하며 기본값은 localhost입니다. 공유 서버·인터넷 공개 지원을 추가한 것은 아닙니다.

[조회 연결·이벤트](../validation/oke-connections-2026-11-10.md), [Pod 로그·이력 연결](../validation/oke-logs-2026-11-10.md), [서버 도구](../validation/oke-tools-2026-11-10.md).

[alpha.8 설치·업데이트·전체 흐름 검증](../validation/alpha8-release-2026-11-10.md).

## alpha.9 반영

새 프로젝트의 첫 소스·빌드 명세 업로드, 명세 읽기 실패, 산출물 전달 권한 확인 방법을 화면 도움말에 추가했습니다. 프로젝트 조회 실패와 정상 빈 목록을 구분하고, 알림·Registry 조회 실패 시 생성 폼을 숨깁니다. CLI 확인 방법은 유지합니다.

새 프로젝트의 빌드·보고서·VM 배포와 임시 조회 전용 계정의 조회 성공·작업 거부를 실제 화면에서 검증했습니다. 404 응답만으로 권한 부족을 단정하지 않으며, 조회 성공도 생성 권한을 보장하지 않습니다. 기존 alpha.8의 미검증 범위는 유지합니다.
