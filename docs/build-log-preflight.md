# 빌드 전에 프로젝트 로그 확인하기

빌드 요청 후 로그 미설정 오류를 만나는 일을 줄이기 위해, Companion은 실행 직전에 현재 리전·구획에서 해당 DevOps 프로젝트의 활성 서비스 로그를 확인합니다. 일반 빌드 실행과 저장된 프로젝트의 빌드 실행에 같은 기준을 적용합니다.

| 상태 | 의미 | 동작 |
|---|---|---|
| READY | 해당 프로젝트의 DevOps `all` 로그가 활성 상태이며 enabled | 기존 검증 후 빌드 요청 |
| DISABLED | 일치하는 로그는 있으나 비활성 또는 준비 중 | 실행하지 않고 활성화·상태 확인 안내 |
| NOT_FOUND | 현재 구획에서 접근 가능한 로그 중 일치 항목 없음 | 실행하지 않고 프로젝트 리소스·OCI 콘솔에서 로그 준비/위치 확인 안내 |
| UNKNOWN | 로그 목록 조회 실패 | 실행하지 않고 연결·Logging 읽기 권한 확인 안내 |

프로젝트가 다른 구획에 속하면 기존 범위 검증으로 거부합니다. 여러 페이지의 로그 그룹·로그를 조회하며, 다른 프로젝트나 다른 서비스의 로그를 성공으로 인정하지 않습니다. 로그를 자동 생성하거나 IAM 정책을 변경하지 않습니다.

현재 점검 범위는 선택한 구획입니다. 다른 구획의 로그가 존재할 수 있으므로 NOT_FOUND는 계정 전체에 로그가 없다는 뜻이 아닙니다. 빌드 실행 권한만 가진 사용자에게 Logging 읽기 권한이 없으면 사전 점검을 통과하지 못합니다. 프로젝트 리소스 화면과 OCI 콘솔에서 필요한 조회 범위를 확인하세요. READY도 러너 확보·소스 접근·빌드 성공을 보장하지 않습니다. 확인 직후 상태 변경에 대비해 OCI의 로그 비활성 오류도 계속 처리합니다.

## IAM 정책 한도 안내

Companion의 권한·실패 가이드에는 TenantCapacityExceeded 발생 시 계정 한도 확인, 기존 정책 재사용, 정확한 파이프라인 주체 추가, 정책을 관리하는 Terraform 상태 및 변경 전후 권한 확인을 안내합니다. 정책 개수·한도 자동 조회나 정책 수정 화면은 아직 없습니다. 관찰했던 500개 한도를 모든 계정에 하드코딩하지 않습니다.

## 확인한 범위

2026-11-06 전체 테스트 114개 통과. 활성·비활성·로그 없음·다른 프로젝트·조회 거절을 검사하고, 비활성/미발견/조회 실패 때 createBuildRun이 호출되지 않는 것을 확인했습니다. 실제 서울 Launchpad 프로젝트에서 구현 어댑터를 읽기 전용 실행하여 READY를 확인했습니다. 브라우저 확장 UI 차단으로 새 안내 화면의 실제 브라우저 검증은 남아 있습니다. 관리형 빌드를 다시 요청한 검증은 아닙니다.
