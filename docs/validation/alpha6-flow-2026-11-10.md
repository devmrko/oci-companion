# alpha.6 독립 ZIP · 빌드에서 VM 배포까지

2026-11-10 KST. DEFAULT / ap-seoul-1 / Joungmin.Ko에서 확인했다.

## 조건

- 별도 폴더에 ZIP을 풀고 빈 로컬 데이터로 8092에서 실행했다. 개발 폴더의 `.env`와 로컬 설정은 복사하지 않았다.
- 기존 검증용 OCI 프로젝트·빌드 파이프라인·Gitea의 OCI Git 복제본·저장소·VM 배포 환경을 재사용했다. OCI 자원까지 모두 없는 테넌시의 첫 구성 검증은 아니다.
- Gitea 소스는 화면에서 새로 등록했다. 이번 실행에 Git 동기화 재수행은 포함하지 않았다.

## 확인

1. 화면에서 빌드 실행을 검토·요청했다. Python 테스트 2개, 빌드와 두 산출물 전달이 모두 성공했다.
2. 화면에서 JUnit 결과, 일반 보고서 다운로드, 빌드 로그, 해당 실행 버전의 Registry 산출물을 확인했다.
3. 새 `hello/app.tar.gz`를 화면에서 선택해 VM 배포 파이프라인을 만들고 실행했다. OCI 성공과 HTTP `{"message":"hello"}` 응답을 배포 로그에서 확인했다.
4. 빌드 화면의 **이 빌드로 배포 준비** → 새 파이프라인 선택에서 SHA-256·크기 일치 안내를 확인했다. 배포 참조의 경로·버전도 SDK로 대조했다.
5. 독립 ZIP의 주요 화면 10개와 빌드→배포 연결 화면을 390/768/1440px로 확인했다. Java 테스트 219개, 브라우저 오류 없음.

빌드·배포 요청과 결과 조회는 실제 브라우저에서 수행했다. SDK는 검증 VM 시작, 제한된 임시 IAM 준비, 산출물 참조 대조에 보조적으로 사용했다. HTTP 요청은 VM의 네이티브 배포 명령이 localhost에서 수행했고 화면의 OCI Logging 로그로 확인했다. 외부 공개 URL·무중단 배포 검증은 아니다.

## 발견 사항

- 저장소에 동일 경로의 과거 버전이 함께 있어 기존 테스트 선택자가 둘을 선택했다. 현재 빌드 실행에서 생성한 버전까지 지정하도록 보완했다.
- VM Run Command가 ACCEPTED에서 대기했다. 검증 VM 하나에 한정한 `request.instance.id = target.instance.id` 조건을 임시 정책에 추가한 뒤 실행 성공을 확인했다. 지연과 권한 변경의 인과관계를 단독으로 확정하지는 않았다.
- 참고: [OCI Run Command](https://docs.oracle.com/en-us/iaas/Content/Compute/Tasks/runningcommands.htm). 앱이 사용자 IAM을 자동 변경하는 기능을 추가한 것은 아니다.

## 재현 자료

`scripts/browser-onboarding-build.cjs`는 `COMPANION_TEST_URL`, `COMPANION_ONBOARDING_STATE`, `COMPANION_RUN_NAME`을 받는다. 쓰기 검증에는 `COMPANION_UI_BUILD_WRITE=1`, 실행에는 `COMPANION_ONBOARDING_RUN=1`이 필요하다. 기존 실행 ID가 상태 파일에 있으면 새 빌드를 만들지 않고 이어서 확인한다.

로컬 `.tools/alpha6-flow-state.json`, `alpha6-vm-state.json`, `alpha6-artifact-link.json`과 UI 캡처에 실행 근거를 보관했다. 계정 OCID와 전체 로그는 공개 ZIP에 포함하지 않는다.

## 이전 버전 복구

- 기존 v1 파이프라인을 화면에서 다시 실행했다. OCI SUCCEEDED와 화면 로그의 HTTP `version: v1`을 확인했다.
- 이전 버전의 명시적 재배포이며 자동 롤백·DB 복원 검증은 아니다.
- 새 빌드에서 다른 산출물을 쓰는 v1 파이프라인을 선택하면 파일 불일치 안내가 나타나고 실행 버튼이 제공되지 않음을 확인했다. 복구는 새 빌드 연결 밖에서 명시적으로 이전 파이프라인을 선택했다.

## 정리

VM에서 v1 HTTP 응답을 다시 확인한 뒤 검증 프로세스를 종료했다. VM은 원래 STOPPED 상태로 복원했고, 이번에 만든 임시 IAM 정책과 8092 테스트 서버를 정리했다. 기존 8091 앱은 유지했다. 빌드·배포 이력, 새 산출물과 재현용 배포 구성은 남겼으며 자동 실행 예약은 추가하지 않았다.
