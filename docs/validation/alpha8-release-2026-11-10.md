# alpha.8 설치·업데이트·전체 흐름 검증

2026-11-10 KST, DEFAULT / ap-seoul-1 / Joungmin.Ko. 실제 OCI와 독립 실행 ZIP의 브라우저 화면으로 검증했다. 개발 폴더의 `.env`를 새 설치에 복사하지 않았다.

## 새 설치

- 빈 데이터에서 프로파일·리전·구획 선택 후 Gitea 소스를 화면에서 등록했다.
- 기존 OCI Git 복제본과 검증용 프로젝트·파이프라인을 사용해 새 빌드를 실행했다. Git 동기화를 다시 수행하거나 빈 테넌시의 모든 자원을 처음 생성하는 검증은 아니다.
- Python 테스트 2개, 빌드, 애플리케이션·보고서 전달이 성공했다.
- 화면에서 JUnit 결과, 일반 보고서 다운로드, 빌드 로그와 이번 실행 버전의 Registry 산출물을 확인했다.
- 이번 실행의 `hello/app.tar.gz`를 선택해 새 VM 배포 파이프라인을 화면에서 생성·실행했다. OCI SUCCEEDED와 로그의 HTTP `message: hello`를 확인했다. 외부 공개 HTTP나 무중단 배포 검증은 아니다.
- 빌드 → 배포 연결의 SHA-256·크기 일치와 다른 산출물 실행 차단을 확인했다. 두 곳의 같은 안내 문구로 기존 브라우저 선택자가 실패해 첫 번째 안내를 선택하도록 검증 스크립트를 수정했다. 앱의 실행 차단은 정상 동작했다.
- 주요 10개 화면과 빌드→배포 연결을 390·768·1440px에서 확인했다. 브라우저 오류와 가로 넘침이 없었다.
- 기존 v1 파이프라인을 화면에서 명시적으로 재배포했다. OCI SUCCEEDED와 화면 로그의 HTTP `version: v1`을 확인했다. 자동 롤백이나 데이터베이스 복원 검증은 아니다.

## 업데이트

별도 폴더의 alpha.7 ZIP에 운영 설정 복사본을 준비하고 기존 소스·범위·등록 앱을 화면에서 확인했다. 프로세스를 종료한 후 같은 폴더의 JAR만 alpha.8로 교체했다.

- 설정 JSON 319개의 파일 해시가 교체 전후 동일했다.
- 로그인 후 저장 소스 목록·서울/Joungmin.Ko 선택·등록 앱이 유지됐다.
- 기존 OKE 연결로 실제 Deployment 준비 완료 상태를 조회했다. 수정 화면에서 namespace·Deployment 값도 유지됐다.
- OKE kubeconfig는 기존 절대 경로를 유지했다. 폴더 이동의 자동 재연결을 검증한 것은 아니다. 폴더를 옮기면 연결을 다시 저장해야 한다.

## 범위와 한계

Java 256개와 CI를 통과한 코드의 실행 JAR를 사용했다. OCI SDK는 VM 시작, 정확한 산출물 조회, 제한된 임시 IAM 준비 및 상태 대조에 사용했다. 빌드·배포 요청, 보고서와 로그 확인은 브라우저로 수행했다.

Container Instances 사설 이미지 실행은 기존 동적 그룹 한도 제약으로 미완료다. 기존 그룹 삭제나 권한 확대는 하지 않았다. OKE 사설 API 접속·실제 RBAC 제거 상황·외부 신규 사용자 사용성은 미검증으로 남긴다. 이 제한은 알파의 지원 범위에도 표시한다.

개인 OCID·프로파일·전체 로그·설정 복사본은 공개 ZIP에 넣지 않는다. 로컬 실행 근거는 `.tools/alpha8-flow-state.json`, `alpha8-vm-state.json`, `alpha8-upgrade-runtime.json` 및 브라우저 캡처에 있다.
