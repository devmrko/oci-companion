# 배포 재시도의 빌드 선택 유지

2026-11-10. 빌드에서 배포로 넘어온 뒤 실행 결과 화면에 도착하면 선택한 빌드 정보가 사라졌습니다. 이후 재시도는 빌드 파일 일치 확인 없이 일반 배포 미리보기로 열렸습니다.

실행 후 이동 주소와 상태·로그 새로고침, 로그·이력 페이지 이동, 재시도 링크에 원본 빌드 파이프라인·실행 ID를 유지하도록 수정했습니다. 재시도는 새 확인 화면에서 파일 일치 여부를 다시 검증하고 새 일회용 실행 티켓을 발급합니다. 원본 빌드가 없는 일반 배포는 기존 동작을 유지합니다. 과거 OCI 이력에 빌드 연결을 새로 저장하거나 자동 추론하지 않습니다.

## 검증

- Java 220개 통과. 실행 후 이동 주소에 원본 빌드 유지, 파일 불일치 시 새 티켓 미발급, 중복 실행 방지 확인.
- 실제 DEFAULT / 서울 / Joungmin.Ko의 기존 VM 배포 이력에서 상태·로그 새로고침 → 재시도 후 URL·화면의 원본 빌드 유지 확인.
- 정리된 VM이 STOPPED이므로 실행 차단 확인. 첫 브라우저 시도는 정상 파일 검증 문구를 기대하여 시간 초과했으며, VM 상태 검사에서 먼저 차단된 것을 확인하고 검증 기대값을 바로잡았습니다.
- 실제 OKE 실패 이력에 다른 파일 빌드를 선택한 상태로 재시도: 파일 불일치 안내, 실행 버튼 없음 확인.
- 390/768/1440px 가로 넘침 없음. 브라우저 JavaScript 오류 없음.

이번 검증에서 새 배포·VM 시작·IAM 변경은 하지 않았습니다. POST 후 이동과 정상 파일 확인은 서버 테스트, 실제 화면에서는 읽기·재시도 미리보기와 차단을 검증했습니다.

재현: `COMPANION_TEST_PROFILE=DEFAULT node scripts/browser-deployment-retry.cjs`. 이전 검증 메타데이터 `.tools/alpha6-flow-state.json`, `.tools/alpha6-vm-state.json`, `.tools/private-oke-first-run.json`이 필요합니다. 로컬 화면 근거는 `.tools/deployment-retry-proof.png`(중지 VM 차단), `.tools/deployment-retry-mismatch.png`입니다.
