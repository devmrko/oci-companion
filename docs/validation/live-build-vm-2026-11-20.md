# 실제 빌드·VM 배포 검증

2026-11-20. DEFAULT / 서울 / 선택 구획. 기존 Gitea 검증 소스의 OCI 복제본과 Python 빌드 파이프라인, 검증 전용 VM을 사용했다.

## 화면에서 수행

1. 새 빌드 실행 `companion-ui-flow-20261120` 요청.
2. 빌드·Registry 전달 `SUCCEEDED`, 실제 로그와 이번 버전의 앱·보고서 산출물 확인.
3. 보고서 조회: 테스트 2, 실패 0, 오류 0, 제외 0. 상태 표시 초록 확인.
4. 이번 실행의 앱 파일로 새 VM 배포 파이프라인 생성. 전용 디렉터리와 `127.0.0.1:18081` 사용.
5. 빌드→배포 SHA-256·크기 일치 확인 후 실행.
6. 권한 보완 후 재실행 `SUCCEEDED`. 배포 로그의 HTTP 응답 `{"message": "hello"}` 확인.

외부 공개 HTTP·무중단 배포·OKE·Container·Function 검증은 이번 범위에 포함하지 않았다. 기존 소스·VM·네트워크를 사용했으며, 새 테넌시 최초 구성 검증이 아니다.

## 부족한 조건 → 해결

- 배포 필수값을 비운 상태에서 제출 차단. 값을 입력한 뒤 설정 검토·생성 통과.
- 첫 배포는 `Identify instances` 단계에서 실패. 사용자 프로파일의 VM 조회는 성공했다.
- 검증 파이프라인·구획의 Compute 읽기와 명령·산출물 접근, 해당 VM의 자기 명령 수행에 한정한 임시 정책 적용.
- 재실행에서 VM 식별 통과. Audit에서 명령 생성 200, VM 명령 수신 204, 산출물 읽기 200 확인.
- 에이전트의 명령 수신 지연 후 실행 완료. 원인을 네트워크·캐시 중 하나로 단정하지 않았다.
- SDK는 VM 시작·복원, 임시 IAM, 상태·Audit 대조에 사용했다. 빌드·배포 요청과 보고서·응답 확인은 Orca 브라우저에서 수행했다.

## UI 보완

실패 실행에 접힌 ‘실패 원인·권한 확인’ 안내를 추가했다. VM 식별, 명령 실행, 다운로드, 앱 상태 확인, OKE 명세 적용별 확인 항목과 OCI 정책 위치·공식 명세를 연결한다. 실패 원인을 권한으로 단정하거나 앱에서 정책을 자동 변경하지 않는다.

기존 공통 정보 레이아웃 사용. Java 272개 통과. 실제 실패 이력과 390px 화면에서 안내·가로 넘침 없음 확인.

참고: [OCI DevOps IAM](https://docs.oracle.com/en-us/iaas/Content/devops/using/devops_iampolicies.htm).

개인 OCID·키·전체 로그는 공개 문서에 포함하지 않는다. 실행 근거와 복원 상태는 로컬 `.tools/live20261120-state.json`에 기록했다.

## 정리

검증 VM을 원래 STOPPED 상태로 복원했다. 이번 임시 정책을 삭제하고 조회 404를 확인했다. 새 빌드·배포 이력과 산출물은 근거로 보존했다.
