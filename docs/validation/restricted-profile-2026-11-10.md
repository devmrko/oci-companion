# 조회 전용 프로파일 검증 — 2026-11-10

임시 IAM 사용자·그룹·API 키·정책을 만들고, 별도 서버에서 실제 OCI와 브라우저로 확인했다. 기존 사용자의 권한과 데모 데이터는 변경하지 않았다.

## 확인한 동작

| 조건 | OCI 응답 및 화면 |
| --- | --- |
| 테넌시·구획 및 DevOps·알림 조회만 허용 | 프로파일 연결, 프로젝트·알림 목록 조회 성공 |
| 알림 주제 생성 요청 | 네이티브 API는 404 `NotAuthorizedOrNotFound`. 화면에 생성 결과 확인 안내와 OCI 권한 설정 도움말 표시 |
| Artifact Registry 권한 없음 | 네이티브 API는 403 `DENIED`. 화면에 조회 실패 표시, 생성 폼 숨김, CLI 도움말 유지 |
| 임시 정책에서 DevOps·알림 조회 권한 제거 | 두 API 모두 404 `NotAuthorizedOrNotFound`. 프로젝트·알림 화면에 조회 실패 표시, 생성 폼 숨김 |

정책 변경 직후 첫 화면 검증은 전파 대기로 실패했다. 네이티브 API의 거부 응답을 확인한 후 다시 실행해 통과했다. 404만으로 권한 부족과 리소스 부재를 구분하지 않는다. 조회 성공도 생성 권한을 뜻하지 않으며, 실제 작업의 허용 여부는 OCI가 판단한다.

## 수정 및 회귀 검증

- 프로젝트의 정상 빈 목록과 조회 실패를 구분한다.
- 알림 조회 실패 시 알림 주제를 새로 만들라는 안내를 숨긴다.
- 알림·Registry 목록 조회 실패 시 생성 폼을 제공하지 않는다.
- Registry 조회가 실패해도 CLI 확인 방법을 유지한다.
- Java 테스트 259개 통과. 실제 브라우저에서 390·768·1440px 가로 넘침 없음.

로컬 검증 근거: `.tools/restricted-profile/`의 비밀값을 제외한 응답 JSON·화면 캡처. 개인 OCID, API 키, 프로파일 설정, 전체 로그는 저장소에 포함하지 않는다. 모든 메뉴·모든 IAM 정책 조합을 검증한 것은 아니다.

## 정리

관리자 조회로 테스트 알림 주제가 생성되지 않았음을 확인했다. 격리 서버를 종료하고 임시 API 키·정책·그룹 멤버십·그룹·사용자를 삭제했다. 로컬 임시 개인키와 프로파일 설정도 삭제했다. 기존 사용자 정책은 변경하지 않았다.
