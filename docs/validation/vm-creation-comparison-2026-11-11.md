# VM 신규 생성 비교 검증 — 2026-11-11

새 VM 생성·SSH 접속은 다른 OCI 프로파일에서 성공했다. DEFAULT의 생성 오류는 해결되지 않았다. 기존 VM 재사용을 신규 생성 성공으로 계산하지 않는다.

## 실제 확인

- 동일 서울 리전, Oracle Linux 8 플랫폼 이미지, VM.Standard.E4.Flex, 1 OCPU·4GB 메모리·50GB 부트 볼륨으로 비교했다.
- DEFAULT: LaunchInstance가 404 NotAuthorizedOrNotFound로 실패했다. 임시 사용자·그룹, 대상 구획의 instance/volume/network 권한, 이미지 읽기 권한을 추가한 경우도 실패했다.
- 다른 테넌시의 프로파일: 격리 VCN·서브넷에서 신규 생성 후 RUNNING, 키 기반 SSH 접속과 x86_64 응답을 확인했다.
- alpha.11 독립 실행본의 실제 브라우저에서 해당 프로파일과 서울 리전·루트 구획을 선택했다. 배포 환경 → VM 조회·확인에 새 VM과 RUNNING, 1 OCPU/2 vCPU, 4GB, 부트 볼륨 50GB가 표시됐다.
- Run Command 실행 상태·배포 권한·런타임은 화면에서 미확인으로 유지됐다. SSH 접속 성공을 DevOps 배포 준비 완료로 간주하지 않았다.

## 진단 한계

이미지·서브넷·AD 조회 성공, E4/E5 한도 여유를 확인했다. DEFAULT에서 이미지·서브넷·공인 IP·기본 용량 예약 적용 여부를 바꿔도 생성에 실패했다. Audit에도 구체적인 거부 조건이 없었다. 다른 테넌시 성공은 요청 형식의 유효성을 뒷받침하지만 DEFAULT의 권한·테넌시 조건 중 원인을 특정하지는 못한다.

생성은 Python OCI SDK, 화면 조회는 실제 앱에서 수행했다. 앱에는 기존 VM 연결·조회 기능이 있으며 새 VM 생성 도우미는 후속 구현이다. 이번 검증은 새 VM에 대한 DevOps 배포를 포함하지 않는다. 기존 VM의 실제 배포·복구 검증은 [별도 기록](vm-deployment-live-2026-11-09.md)을 참고한다.

## 정리

검증 VM의 TERMINATED와 부트 볼륨 삭제, 전용 서브넷·라우트 테이블·게이트웨이·보안 목록·VCN 삭제를 확인했다. 임시 IAM 사용자·그룹·API 키·정책 3개와 로컬 검증 키를 삭제했다. 격리 앱 서버와 압축 해제본도 제거했다. 기존 데모 서버·VM·OKE는 변경하지 않았다.
