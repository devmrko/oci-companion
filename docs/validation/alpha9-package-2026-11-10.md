# alpha.9 설치·업데이트 검증

2026-11-10 KST. PR #35·#36의 도움말·조회 실패 처리를 포함한 실행 ZIP을 독립 폴더에서 검증했다. 실제 OCI DEFAULT 프로파일과 브라우저를 사용했다.

## 새 설치

개발 폴더의 `.env`나 데이터를 복사하지 않고 ZIP을 풀어 `run.sh`로 기동했다. 프로파일 연결, 서울 리전·검증 구획 선택 후 주요 10개 화면과 프로젝트·알림·Registry 목록 및 생성 폼을 확인했다. 390·768·1440px에서 가로 넘침과 브라우저 오류가 없었다.

이번 패키지 검증에서는 클라우드 생성·빌드·배포를 다시 실행하지 않았다. 최근 코드의 실제 생성·빌드·배포 근거는 [새 프로젝트 검증](first-project-2026-11-10.md), 권한 거부 근거는 [조회 전용 계정 검증](restricted-profile-2026-11-10.md)에 있다.

## alpha.8에서 업데이트

별도 폴더에 alpha.8 ZIP과 기존 로컬 설정 복사본을 준비했다. 기존 소스·리전·구획·등록 앱을 화면에서 확인하고 프로세스를 종료한 뒤 JAR만 alpha.9로 교체했다.

- 설정 JSON 319개의 파일 해시가 교체 전후 동일했다.
- 로그인 후 소스 목록·서울 리전·선택 구획·등록 앱이 유지됐다.
- 기존 OKE 연결로 실제 Deployment의 준비 완료 상태를 조회했다.
- OKE 연결 수정 화면의 namespace·Deployment 값이 유지됐다.

OKE kubeconfig의 기존 절대 경로를 사용했다. 설치 폴더 이동 시 자동 재연결을 검증한 것은 아니다.

## 패키지 및 범위

Java 테스트 259개가 통과했다. ZIP에는 JAR·실행 스크립트·안내·검증 문서만 허용하며, 실행 검증한 JAR와 ZIP 내부 JAR의 SHA-256 일치를 확인했다. 개인 설정·OCI 프로파일·인증·로그는 포함하지 않는다.

로컬 근거는 `.tools/alpha9-*.log`, `alpha9-tested-jar.json`, `alpha9-upgrade-runtime.json` 및 화면 캡처다. Container Instances 사설 이미지 실행, OKE 사설 API·실제 RBAC 제한, 외부 신규 사용자 검증은 이번에 수행하지 않았다.

검증 후 8092·8093 서버를 종료하고 로컬 설정 복사본을 포함한 임시 설치 폴더를 삭제했다. 기존 8091 데모와 원본 설정은 유지했다.
