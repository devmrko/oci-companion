# OKE 최소 권한 검증

2026-11-10. Codex가 실제 OCI 계정과 브라우저로 확인했습니다. DEFAULT 관리자는 검증용 IAM 사용자·그룹·API 키·정책과 독립 namespace를 준비했습니다. 기존 사용자나 업무 workload 권한은 변경하지 않았습니다.

## 화면 결과

| 조건 | 결과 |
| --- | --- |
| IAM use clusters, Kubernetes Role 없음 | namespace·Deployment 조회 거부 표시 |
| namespace에 deployments/replicasets/pods get,list 부여 | namespace 목록은 계속 거부. 이름 직접 입력 → Deployment 조회 → 연결 저장 → 준비 완료 |
| pods/log 권한 없음 | 로그 조회 불가, 필요한 권한 안내 |
| pods/log get 추가 | fixture nginx Pod의 실제 시작 로그 조회 완료 |
| pods/log get 회수 | 같은 화면에서 다시 조회 불가 |

OKE 조회 연결과 Pod 로그 화면에 공유 도움말을 추가했습니다. OCI 콘솔 정책 위치, use clusters 예제, namespace Role/RoleBinding, 적용 명령, 선택적인 events·nodes 권한을 구분합니다. cluster-admin은 필요하지 않습니다. 화면 도움말은 390·768·1440px에서 열어 확인했습니다.

## 사설 API 제한

공인 API는 실제 연결됩니다. 앱 서버에서 사설 API 주소는 도달하지 못하며 PRIVATE_ENDPOINT 선택 후 조회 실패가 표시됐습니다. 임시 OCI Bastion은 서비스 한도로 생성되지 않았습니다. 별도 NSG와 클라이언트 IP /32 SSH 규칙을 준비했으나 임시 VM 생성은 E4·E5 모두 NotAuthorizedOrNotFound(404)로 실패했습니다. 구획·서브넷·이미지·가용성 도메인은 조회됐습니다. 404만으로 원인을 IAM 부족이라고 단정하지 않습니다.

따라서 사설 API 성공, VPN·Bastion 경유 조회는 검증 완료로 표시하지 않습니다. 기존 네트워크 규칙은 변경하지 않았습니다.

## 범위

독립 namespace의 nginx 1개와 임시 사용자만 사용했습니다. 업무 Deployment·노드·Secret·운영 앱 로그는 변경하거나 읽지 않았습니다. 기본 Role에는 namespace 목록, events, nodes 권한이 없으며 각 선택 조회의 실패는 본문과 구분됩니다. 이는 모든 테넌시와 RBAC 조합에 대한 보장이 아닙니다.

공식 기준: [OCI 접근 제어](https://docs.oracle.com/en-us/iaas/Content/ContEng/Concepts/contengaboutaccesscontrol.htm).

검증 후 전용 namespace, 임시 NSG, 테스트 서버, IAM API 키·정책·그룹·사용자와 로컬 개인 키·설정 파일을 제거했습니다. 대체 VM은 생성되지 않았습니다.
