# 범위 변경과 alpha.5 실행본 검증 — 2026-11-09

빌드 설정, 새 명세 작성, 등록 앱 상태 화면이 선언한 scopeBack 경로가 전역 범위 변경 허용 목록에 빠져 있었습니다. 세 경로를 추가해 리전·구획 적용 후 현재 메뉴로 돌아갑니다. 외부 URL이나 임의 쿼리로 이동시키지 않는 정확한 허용 목록은 유지했습니다. 등록 앱 상태의 구현되지 않은 /operations/tools 링크를 제거했습니다.

- 직접 문자열로 선언한 scopeBack 16개를 허용 목록과 대조해 누락 없음 확인. 동적으로 구성하는 Registry 경로는 별도로 유지합니다.
- Java 219개 통과. 세 화면의 실제 폼 back 값과 /scope 리다이렉트, 외부 URL·임의 경로 거부 검증.
- alpha.5 ZIP을 별도 폴더·빈 데이터·.env 없는 환경에서 실행했습니다. ZIP 내 JAR와 테스트한 JAR의 SHA-256 일치를 확인했습니다.
- 실제 DEFAULT / 서울 / Joungmin.Ko에서 세 화면의 범위 적용 후 메뉴 유지 확인. 실제 클라우드에서는 동일한 리전·구획을 적용했으며, 다른 범위 선택은 웹 통합 테스트에서 확인했습니다.
- 실제 OCI 10개 화면: 소스, 빌드, 배포 이력, OKE 배포 구성, Container 준비, 백업·복구, 정기 정책, 빌드 설정, 새 명세 작성, 등록 앱 상태. 각 390/768/1440px 문서 가로 넘침 없음.
- 클라우드 리소스 변경 없음. 등록 앱 상태는 빈 목록 검증이며 실제 앱 연결·건강 검사 성공을 뜻하지 않습니다.
- 재검증: `COMPANION_TEST_PROFILE=DEFAULT node scripts/browser-scope-navigation.cjs`. Playwright 설치 필요. 다른 서버 주소는 COMPANION_TEST_URL로 지정합니다.
