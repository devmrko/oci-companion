# OKE 로그·배포 후 조회·연결 해제 검증

2026-11-10. 등록 앱 상태 → Pod 로그. 배포 실행 이력 → 앱 상태·Pod 로그.

## 구현

- 현재 앱 Deployment·ReplicaSet 소유 UID로 Pod 목록을 한정한다. 일반·init 컨테이너를 선택하고 최근 100/200/500줄, 최대 64KiB를 읽는다. 현재 또는 직전 컨테이너 실행을 선택한다.
- native kubectl logs를 사용한다. 셸·임의 명령·사용자 kubeconfig 경로를 받지 않는다. 연결 범위와 소유 관계를 다시 확인하고, 읽기 전후 Pod UID가 달라지면 결과를 버린다. 로그 원문을 서버 파일이나 세션에 보관하지 않는다. 템플릿은 text로 출력한다.
- 배포 실행에 기록된 환경 ID를 OCI에서 읽고, 그 환경의 현재 OKE 클러스터와 같은 로컬 조회 연결을 보여준다. 현재 파이프라인을 배포 당시 설정으로 오인하지 않는다. 같은 클러스터라는 관계만 확인하며 당시 앱/버전 일치나 배포 정상 여부를 추정하지 않는다.
- OKE 조회 연결 해제는 확인 체크·CSRF·범위 확인 후 로컬 등록, 바인딩, 해당 현재 생성 kubeconfig만 정리한다. 관리자 파일은 삭제하지 않는다. 클라우드 API 삭제 호출은 없다. 이후 연결 수정도 직전 생성 kubeconfig를 정리한다. 이전 버전에서 남긴 참조 없는 파일 전체를 일괄 삭제하지는 않는다.

## 검증 결과

Java 254개 통과. 로그 소유 Pod·UID·컨테이너 제한, 조회 중 Pod 교체 시 원문 폐기, 현재/직전 고정 인수와 크기·줄 수, 빈 로그/조회 실패 구분, 구획 변경 거부, 관리 파일 외 삭제 거부, 해제 시 클라우드 미호출, 이력의 환경 참조 사용을 확인했다.

실제 서울 OKE에 별도 namespace와 소형 Deployment를 생성했다. writer 컨테이너가 표식을 출력하고 종료·재시작하도록 구성했으며 sidecar는 별도 표식을 출력했다. 화면에서 컨테이너 선택, 현재 sidecar 로그, writer 직전 실행 로그와 시각을 확인했다. 잘못된 Pod UID로 요청하면 로그가 표시되지 않았다.

기존 OCI 배포 이력에서 앱 확인으로 이동하고, 같은 클러스터의 검증 연결과 새 연결 화면의 클러스터 선택 유지를 확인했다. 연결 해제 POST는 CSRF 없으면 403. 확인 후 해제하면 로컬 바인딩과 현재 kubeconfig 파일이 삭제됐다. 직후 OCI Deployment가 여전히 1 replica로 존재함을 확인했다. 390/768/1440px 화면 넘침과 JavaScript 오류 없음.

검증용 namespace 삭제, 8092 서버 및 임시 생성 연결 파일 정리. 기존 workload·노드·IAM은 변경하지 않았다.

## 재현·한계

scripts/browser-oke-logs.cjs에 COMPANION_TEST_PROFILE/REGION/COMPARTMENT/CLUSTER/NAMESPACE/DEPLOYMENT/PIPELINE/RUN과 COMPANION_TEST_WRITE_LOCAL=1을 지정한다. 테스트 대상은 writer/sidecar 컨테이너와 companion-before-restart/companion-sidecar-log 표식이 있는 격리된 Deployment를 준비한다. 스크립트는 로컬 연결 생성·해제를 수행하며 클라우드 리소스를 만들거나 삭제하지 않는다. 기본 URL은 8092이며 COMPANION_TEST_URL로 변경한다.

pods/log get 권한이 필요하다. 직전 실행은 Kubernetes가 보존한 동일 Pod 컨테이너의 이전 로그이며 과거 모든 배포 로그가 아니다. 삭제된 Pod, 회전으로 사라진 로그, 장기 보관·스트리밍은 지원하지 않는다. 로그가 권한 부족인지 소실됐는지 확정할 수 없으면 조회 불가로 표시한다. 실제 RBAC 권한 제거 실험은 하지 않았다.
