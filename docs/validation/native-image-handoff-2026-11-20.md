# 빌드 이미지 → OKE 배포 일치 검증

2026-11-20. 기존 BuildHandoff 인터페이스·OCI 어댑터·명세 검사·실행 티켓을 확장했다. Foundation의 MVC·인증·오류 처리를 유지하며 새 의존성이나 별도 버전 DB를 추가하지 않았다.

## 동작

- 선택한 성공 빌드의 OCI 전달 기록에서 이미지 주소와 SHA-256 digest를 읽는다.
- 빌드 화면에 기록된 버전을 표시한다. 기록이 있으면 빌드 실행 ID를 배포 화면으로 전달한다.
- 준비된 OKE 파이프라인의 모든 컨테이너·init 컨테이너 주소와 digest가 해당 빌드의 전달 기록에 있어야 실행할 수 있다. 사이드카도 예외 없이 비교한다.
- 이미지 태그만 있는 명세, 다른 저장소·digest, 누락·충돌한 기록은 검증 실패다. 현재 태그나 현재 파이프라인 설정으로 과거 실행의 버전을 추정하지 않는다.
- 실행 직전 기존 티켓 검증에서 빌드 기록과 배포 명세를 다시 읽는다. 변경되면 실행하지 않는다.
- 파일 배포의 SHA-256·크기 검증은 유지한다. 배포 이력 조회는 원본 빌드가 없어져도 이를 새로 읽지 않는다.

현재 경로는 **준비된 OKE 파이프라인 선택·비교**다. 빌드에서 새 OKE 구성을 자동 생성하거나 Container Instances·Functions에 이미지를 전달하는 기능은 포함하지 않는다.

## 실제 OCI 확인과 한계

DEFAULT / 서울 / 검증 구획의 최근 성공 실행 30건을 읽었다. 그 안에서 이미지 주소와 digest가 모두 채워진 컨테이너 전달 기록을 찾지 못했다. 이전 OKE 실검증 실행은 `imageUri`, `deliveredArtifactHash`가 빈 문자열이었다. 성공 실행 30건 모두가 컨테이너 빌드라는 뜻은 아니다.

실제 앱 화면에서 해당 빌드의 ‘실행 기록의 이미지 주소·digest 확인 불가’를 확인했다. 같은 실행과 기존 OKE 파이프라인을 연결하면 일치 확인 실패를 표시하고 실행 버튼이 나오지 않았다. 이 경로로 클라우드 배포를 실행하지 않았다.

**자동 연결 성공의 실제 OCI 검증은 미완료**다. 단위 테스트의 성공 사례를 실제 클라우드 검증으로 보지 않는다. OCI 기록이 있는 실행을 확보하거나, 별도로 네이티브 빌드 출력에 digest를 남기는 방법을 설계·검증해야 한다. 수동 Registry 선택은 여전히 별도 배포이며 빌드 일치 검증 성공을 뜻하지 않는다.

## 코드 검증

Java 테스트 279개 통과. 같은 이미지, OCI 호스트 별칭, 다른 저장소·digest, 태그 전용 명세, 미등록 사이드카, 누락·충돌 기록, 실패 빌드, OKE 단계와 변경된 명세를 검사했다. 기존 파일 배포 테스트도 통과했다.

근거: [OCI Java SDK ContainerRegistryDeliveredArtifact](https://docs.oracle.com/en-us/iaas/tools/java/latest/com/oracle/bmc/devops/model/ContainerRegistryDeliveredArtifact.Builder.html). 명세는 전달된 이미지의 hash와 URI 필드를 제공한다. 필드 정의가 실제 반환값의 존재를 보장하지는 않았다.
