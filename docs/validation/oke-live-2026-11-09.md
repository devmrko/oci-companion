# OKE 배포·이전 버전 복구 실검증

2026-11-09. DEFAULT 프로파일, 서울 리전의 전용 검증 파이프라인과 Namespace에서 실행했습니다. 기존 서비스의 명세·노드·네트워크는 변경하지 않았습니다.

## 화면 검증

- 배포 화면에서 공식 nginx amd64 digest 이미지의 v1을 실행하고 성공·로그를 확인했습니다.
- 별도 v2 명세 산출물을 연결한 뒤 같은 화면에서 실행했습니다. OCI 실행 스냅샷과 실제 리소스 로그에서 `VALIDATION_VERSION=v2`를 확인했습니다.
- v1 이력의 **이 버전으로 복구** → 확인 → 실행으로 복구했습니다. `SUCCEEDED`, 실제 리소스 로그의 `VALIDATION_VERSION=v1`을 확인했습니다.
- 실행 권한 도움말의 선택 파이프라인·클러스터 표시와 390/768/1440px 화면을 검증했습니다.

이 검증은 OCI rollout·readiness와 실제 리소스 상태 기준입니다. 외부 사용자 경로의 HTTP 부하·무중단 전환 검증은 포함하지 않습니다.

## 발견한 문제와 처리

파이프라인 실행 주체에는 프로파일 사용자와 별도 권한이 필요했습니다. 전용 파이프라인 ID, 지정 클러스터의 CLUSTER_READ/USE/MANAGE, 지정 프로젝트의 산출물 읽기, 선택 구획의 GetSubnet만 허용했습니다. 앱은 IAM을 자동 변경하지 않으며 같은 조건의 도움말을 제공합니다.

`target.subnet.id`는 Core 정책의 지원 조건 변수가 아니었습니다. Audit에서 클러스터 조회와 kubeconfig 생성은 성공했지만 GetSubnet이 실패한 것을 확인했습니다. 지원되지 않는 조건을 제거하고 파이프라인·구획·GetSubnet 제한을 유지하자 배포가 진행됐습니다.

같은 INLINE 산출물의 본문을 v2로 수정한 직후 실행에서는 이전 v1 스냅샷이 관찰됐습니다. 원인은 확정하지 않았습니다. 검증에서는 별도 v2 산출물을 만들고 단계에 연결해 실제 버전 변경을 확인했습니다. 실행 성공만으로 새 버전 적용을 판정하지 않았습니다.

사설 이미지 인증이 준비되지 않은 첫 시도와 버전이 바뀌지 않은 재실행은 성공 검증에서 제외했습니다. 최종 복구 검증은 실제 v2 → v1입니다.

## 재현 자료

로컬 `.tools/oke-live-v1.json`, `oke-live-v2.json`, `oke-live-rollback.json`에 실행 참조가 있습니다. `oke-v2-ui.txt/png`, `oke-rollback-ui.txt/png`는 실제 화면 증거입니다. 계정 리소스 ID와 전체 로그는 공개 저장소에 올리지 않습니다.
