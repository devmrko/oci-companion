처음 소스 올리기 ?

저장소 생성만으로 소스가 들어가지는 않습니다. 빌드할 소스와 build_spec.yaml을 Git에 커밋한 후 위 저장소 주소로 올리세요. 빌드 단계에서 같은 저장소·브랜치와 명세 경로를 선택합니다.

git remote add oci <위 저장소의 HTTPS 주소>
git push oci HEAD:refs/heads/<빌드할 브랜치>

기존 로컬 Git 폴더에서 실행합니다. 이미 oci remote가 있으면 주소를 먼저 확인하세요. Git 쓰기 인증은 OCI 프로파일과 별도이며, 인증값을 명령이나 소스에 넣지 마세요. OCI 콘솔 → DevOps → 프로젝트 → 코드 저장소에서 연결 주소를 확인할 수 있습니다.

Gitea 연결 ?

Gitea는 OCI Managed Build의 기본 소스 연결 대상이 아닙니다. Gitea 설정 → Repository → Mirror Settings에서 전용 OCI 코드 저장소로 Push Mirror를 구성할 수 있습니다. OCI Git 쓰기 인증이 필요합니다. 미러 대상은 Gitea 내용으로 덮어쓰므로 기존 업무 저장소를 사용하지 마세요.

동기화 후 아래 파이프라인에서 OCI 저장소를 선택합니다. Git 인증은 OCI 프로파일 서명과 별개입니다.

로그 그룹 생성
파이프라인 구성소스 목록
OCI에서 수행·권한 ?

DevOps → 프로젝트 → 코드 저장소 → 저장소 생성. 로그 → 로그 사용.

현재 프로파일에 선택 구획의 devops-repositories, log-groups 생성·조회 권한이 필요합니다. 빌드 리소스의 저장소 읽기·로그 기록·산출물 쓰기 권한은 IAM에서 별도로 설정합니다.

oci devops repository create --project-id <프로젝트 OCID> --name <이름> --repository-type HOSTED
oci logging log-group list --compartment-id <구획 OCID> --all
oci logging log create --log-group-id <로그 그룹 OCID> --display-name <이름> --log-type SERVICE --configuration file://configuration.json --is-enabled true

현재 프로파일·리전을 --profile, --region으로 지정합니다.
