기존 Ingress·TLS 연결 · 선택 ?
앱 서버에서 공개 HTTPS 443에 HEAD 요청합니다. 인증정보·본문은 수집하지 않습니다. DNS 첫 주소 1개 점검이며 앱 기능 정상 여부와는 별도입니다.
점검 기준·직접 확인 ?
DNS와 Ingress 주소가 다르면 CDN·별칭을 확인하세요. TLS는 신뢰 체인·호스트명·유효기간을 확인하며, 30일 미만이면 주의로 표시합니다. 인증서 폐기 상태와 사설 주소는 별도 확인합니다.
kubectl -n <namespace> get ingress <name> -o wide
nslookup <host>
curl --head --max-time 10 https://<host>/<path>
openssl s_client -connect <host>:443 -servername <host> -verify_hostname <host> -verify_return_error
OCI 콘솔: Kubernetes Clusters → 클러스터 → Access Cluster. 공개 DNS는 Networking → DNS Management에서 확인하세요.
기존 Ingress가 이 앱의 ClusterIP Service로 연결되는지 점검합니다. Ingress·DNS·인증서를 생성하거나 변경하지 않습니다. 공개 주소의 인증서·HTTP 상태는 실제 접속 점검으로 확인하세요.
기존 LoadBalancer Service는 조회만 제공합니다. 신규 Gateway API 연결은 후속 지원입니다.

OCI 작업·권한 ?
Developer Services → DevOps → 프로젝트 → Deployment Pipelines에서 OKE 단계를 구성합니다. 명세는 표준 Kubernetes YAML이며 앱 없이 적용할 수 있습니다.
oci devops deploy-stage create-deploy-oke-stage --help
kubectl apply --dry-run=server -f deployment.yaml
kubectl apply -f deployment.yaml
사용자에게 프로젝트·배포 파이프라인·아티팩트·단계 관리와 이미지 읽기 권한이 필요합니다. DevOps의 클러스터 접근 권한, 노드의 OCIR 읽기 권한은 별도로 필요합니다. 관리자에게 IAM → Policies에서 필요한 프로젝트·구획 범위로 설정하도록 요청하세요.
Service는 ClusterIP입니다. 외부 공개는 기존 Ingress·Load Balancer 구성을 연결하세요. CPU·메모리는 Pod 설정이며 노드 사양을 변경하지 않습니다.
