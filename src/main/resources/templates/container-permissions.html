사설 OCIR 인증 확인 ?

화면에서 이미지가 보여도 Container Instances의 다운로드 권한은 별도로 필요합니다.

생성 전에 policy 준비 ?

OCI 콘솔 → ID 및 보안 → 정책 → 저장소 구획 또는 상위 구획 → 정책 생성 → 수동 편집기. 실행 구획과 저장소를 지정하고 정책 전파 후 생성하세요.

Allow any-user to read repos in compartment id <저장소 구획 OCID> where all {
  request.principal.type='computecontainerinstance',
  request.principal.compartment.id='<실행 구획 OCID>',
  request.region='ICN',
  target.repo.name='<저장소 이름>'
}

해당 실행 구획의 현재·향후 Container Instances에 적용됩니다. 전용 실행 구획을 사용하세요. ICN은 서울 리전 키입니다. 다른 리전은 공식 리전 키로 바꾸세요. 저장소 이름에는 namespace·태그·digest를 넣지 않습니다.

인스턴스가 생성되면 아래 OCID 조건으로 한 대만 허용할 수 있습니다. 기존 정책을 그대로 두고 좁은 정책을 추가하면 기존 허용 범위는 유지되므로, 기존 문장을 교체해야 합니다.

인스턴스 한 대에 policy 적용 ?

OCI 콘솔 → ID 및 보안 → 정책 → 저장소 구획 또는 상위 구획 → 정책 생성 → 수동 편집기. 아래 저장소 구획 OCID와 이름을 바꿔 적용하세요.

Allow any-user to read repos in compartment id <저장소 구획 OCID> where all {
  request.principal.type='computecontainerinstance',
  request.principal.id='',
  target.repo.name='<저장소 이름>'
}

any-user는 위 조건으로 지정한 인스턴스 한 대만 허용합니다. 세 조건을 모두 유지하세요. 저장소 이름은 namespace·태그·digest 없이 입력합니다. 새 동적 그룹은 필요하지 않습니다.

생성된 인스턴스의 OCID가 필요합니다. 재생성하면 OCID가 바뀌므로 정책도 갱신해야 합니다. 정책 저장과 이미지 다운로드 성공은 별개이며 전파 후 상태·로그를 확인하세요.

동적 그룹으로 관리

  1. OCI 콘솔 → Developer Services → Container Registry: 이미지 경로·digest와 저장소 구획을 확인하세요.
  2. ID 및 보안 → 도메인 → 동적 그룹: 대상 Container Instance가 일치 규칙에 포함되는지 확인하세요.
  3. ID 및 보안 → 정책: 해당 동적 그룹에 대상 저장소의 읽기 권한을 부여하세요.
  4. Networking → 서브넷: OCIR 접근 경로·DNS·보안 규칙을 확인하세요. 권한 변경은 반영에 시간이 걸릴 수 있습니다.

기존 인스턴스 한 대로 제한하는 동적 그룹 예시입니다. 새 인스턴스에는 그 인스턴스의 OCID를 사용해야 합니다.

ALL {resource.type='computecontainerinstance', resource.id='<인스턴스 OCID>'}

Allow dynamic-group <동적 그룹> to read repos in compartment id <저장소 구획 OCID> where target.repo.name='<저장소 이름>'

동적 그룹 생성이 한도 초과로 거절되면 관리자가 그룹 사용 현황과 서비스 한도를 확인해야 합니다. 기존 그룹을 재사용하려면 일치 규칙뿐 아니라 연결 정책 전체와 다른 리소스에 미치는 영향도 확인하세요. 앱은 기존 그룹을 삭제하거나 IAM 권한을 자동 변경하지 않습니다.

OCIR 사설 이미지는 리소스 주체 IAM을 사용합니다. Vault 이미지 인증은 외부 Registry용입니다. FAILED 생성 건은 원인을 해결한 뒤 삭제·재생성하세요. 같은 생성 요청을 반복하기 전에 OCI 작업 상태를 확인하세요.
